# 专辑全部终稿 Markdown 导出实施计划

## 目标

在内容项目审核台增加“一键导出全部终稿”，由后端按声音顺序组装一份单文件
Markdown，使用每集最新已保存终稿，并为缺稿声音保留占位。

## 任务 1：建立失败优先测试

- 增加后端 Markdown 渲染单元测试，覆盖顺序、最新版本、人工版本、缺稿和空专辑。
- 增加 API 测试，覆盖 404、Markdown 响应类型和正文。
- 更新前端结构测试，要求导出按钮、接口路径、Blob 下载、文件名清理和未保存确认。
- 在实现前运行定向测试并记录预期失败。

## 任务 2：实现后端只读导出

- 在工作流服务增加项目终稿 Markdown 组装方法。
- 一次查询项目声音及每集最新终稿。
- 折叠标题换行，保留终稿内部段落。
- 为空专辑和缺稿声音生成明确占位。
- 在 FastAPI 增加 `GET /api/projects/{project_id}/finals/export`。

## 任务 3：实现前端下载交互

- 在批量生产卡增加“导出全部终稿”按钮。
- 当前终稿有未保存修改时先确认。
- 请求 Markdown 文本，使用 Blob、临时对象 URL 和下载属性触发单文件下载。
- 清理专辑名称中的非法文件名字符并提供默认文件名。
- 导出不受批量生产状态限制，不修改当前项目状态。

## 任务 4：文档与回归

- 更新 README 的专辑审核流程说明。
- 运行导出相关后端定向测试、前端结构测试和 lint。
- 运行后端全量测试与原生 arm64 Node 生产构建。
- 使用真实本地项目调用导出接口，核对集数、顺序、最新正文和缺稿占位。
- 运行 `git diff --check`，更新持续记录并提交实现。
