# 六阶段内容生产提示词工作台实施计划

## 目标

把思维导图、全书知识模块设计、分模块专辑大纲、声音细纲、声音初稿和声音终稿全部
接入现有版本化提示词配置中心；补齐三层拆书材料占位符、项目真实预览、模块输入快照
与声音模块关联，并保持任务锁定、历史兼容和恢复能力。

## 任务 1：提示词注册表扩展

- 在 `backend/app/prompt_config.py` 新增 `mind_map` 和 `album_module_plan` 两个正式模板。
- 将原 `album_outline` 标签改为“分模块专辑大纲”。
- 为六个环节定义语义明确的允许占位符与必要占位符。
- 保留 `book_analysis`、`module_source` 和声音细纲 `source_text` 兼容别名。
- 提升相关系统版本并增加系统保护后缀。
- 更新提示词服务测试，覆盖初始化、校验、继承、历史恢复和兼容别名。

## 任务 2：三层拆书材料构建

- 在 `backend/app/album_planning.py` 增加策划版全书拆书稿渲染器。
- 复用现有完整/压缩拆书稿作为 `full_book_analysis`。
- 使用章节目录条目的主题、子主题和精简观点构造 `planning_book_analysis`。
- 使用模块来源章节的详细拆书稿构造 `module_book_analysis`。
- 增加全书覆盖、顺序、字符预算和内容保留测试。

## 任务 3：模块输入快照与声音关联

- 在 `backend/app/db.py` 为 `episodes` 增加 `planning_run_id` 和 `module_key`。
- 使用 `album_planning_artifacts` 的 `module_source` 产物类型保存模块输入快照。
- 结构化模块大纲时为每条声音保留 `module_key`。
- `_save_generated_album` 写入声音模块关联。
- 增加历史声音惰性恢复：唯一模块匹配、按来源章节生成恢复快照和歧义失败。
- 增加数据库迁移、模块快照和历史恢复测试。

## 任务 4：项目生成工作流接入三个提示词快照

- 项目生成 API 同时锁定 `mind_map`、`album_module_plan` 和 `album_outline`。
- 运行元数据保存三个提示词锁，重启恢复时按锁定版本解析。
- 思维导图从固定 `PROMPTS` 迁移到配置快照。
- 全书知识模块设计从固定 `album_module_plan` 迁移到配置快照。
- 分模块大纲继续使用配置快照，但改用新占位符。
- 单模块重跑复用顶层锁定版本与原模块输入快照。
- 更新阶段输出和运行详情中的提示词版本引用。
- 增加项目任务、恢复、单模块重跑和模型路由测试。

## 任务 5：声音阶段上下文分离

- 在 `backend/app/contexts.py` 为声音细纲提供模块拆书稿变量。
- 声音细纲只渲染 `episode_framework` 与 `module_book_analysis`。
- 来源匹配继续先执行，但其段落级结果只进入声音初稿和终稿。
- 声音初稿继续使用 `episode_outline` 与 `source_text`。
- 声音终稿继续使用 `episode_draft` 与 `source_text`。
- 更新声音任务快照、批量恢复与单条重跑测试，断言细纲不含段落原文。

## 任务 6：项目真实预览 API

- 扩展 `prompt_preview_values` 支持六个环节。
- 思维导图和模块设计预览真实全书材料。
- 分模块大纲支持选择模块；声音三阶段支持选择声音。
- 预览响应增加输入材料清单：名称、来源、字符数、压缩状态和完整内容。
- 缺少项目、模块、声音或可恢复快照时返回明确校验错误。
- 增加预览 API 与敏感输入边界测试；只在显式预览接口返回材料。

## 任务 7：前端六阶段提示词工作台

- 扩展 `PromptStage`、导航标签和编辑状态。
- 编辑区顶部增加实际输入摘要和模型来源说明。
- 为分模块大纲增加模块选择器，为声音阶段保留声音选择器。
- 预览区展示素材清单、字符数、压缩状态和可折叠完整内容。
- 标记必要占位符与旧版兼容占位符。
- 更新 CSS、结构测试、保存校验和响应式布局。

## 任务 8：本地数据版本发布与回归

- 初始化两个新增系统模板并发布六个新版全局默认用户模板，保留全部历史版本。
- 迁移本地 SQLite，但不主动重写现有声音内容。
- 使用现有内容项目检查六个项目级预览和模块关联恢复。
- 运行后端全量测试。
- 运行前端 ESLint、生产构建和结构测试。
- 检查 `git diff --check`、数据库忽略边界和密钥边界。
- 更新 README、持续记录并提交实现。
