# 专辑大纲确定性结构化与失败恢复实施计划

## 目标

用程序直接把已完成的模块 Markdown 转换为专辑页面数据，有限归一内容类型并由模块关系
补入模块键；模型只在确定性解析确实失败时兜底。完成后不调用模型恢复“专辑5”的
15 条声音并进入专辑大纲审核状态。

## 任务 1：解析器契约测试

- 在 `backend/tests/test_album_planning.py` 增加普通标签、加粗标签和一个模块多集测试。
- 增加“深度解读”等允许别名归一测试。
- 增加未知类型、缺失字段、未知章节和跨模块章节失败测试。
- 增加模块键由模块对象补入、顺序稳定和主内容标准化断言。
- 先运行定向测试并记录预期失败。

## 任务 2：确定性 Markdown 解析器

- 在 `backend/app/album_planning.py` 增加内容类型有限映射。
- 增加标题块切分、字段标签兼容、核心要点多行提取和章节标识提取。
- 解析器接收有序模块及模块 Markdown 映射，输出既有 `album_outline` 字典。
- 不改写字段正文，不猜测缺失字段，不放宽章节、模块和数量边界。
- 复用 `validate_structured_outline()` 完成最终验证。

## 任务 3：工作流确定性优先与模型兜底

- 在 `backend/app/workflows.py` 的结构化阶段先调用确定性解析器。
- 成功时直接序列化并保存 `structured_outline`，不调用结构化或 JSON 修复模型。
- 解析失败时保留现有 `album_outline_structure` 与 `json_repair` 兜底。
- 兜底结果继续执行统一内容类型归一和最终结构校验。
- 增加确定性成功零模型调用与非标准 Markdown 触发兜底测试。

## 任务 4：保存与恢复边界

- 抽取或复用现有专辑保存逻辑，确保结构化结果和声音创建处于事务边界。
- 为已失败但模块产物完整的运行增加无模型恢复入口。
- 恢复时读取原运行的章节目录、模块计划和模块大纲，不重新生成模块。
- 已成功恢复的同一运行再次执行时保持幂等，不重复创建声音。
- 增加恢复成功、恢复失败回滚和重复恢复测试。

## 任务 5：“专辑5”无模型恢复
