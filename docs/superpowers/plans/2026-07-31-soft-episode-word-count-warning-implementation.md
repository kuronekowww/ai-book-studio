# 单集字数范围非阻断提醒实施计划

## 目标

把每集字数范围从“生成成功硬门槛”调整为“提示词创作目标 + 终稿审核提醒”：
初稿和终稿直接保存模型原始输出，只有终稿超范围时在页面显示非阻断提醒。

## 任务 1：建立失败优先测试

- 将后端旧的“自动字数修复并失败”测试改为“字数偏差不触发修复”契约。
- 增加完整声音工作流测试：短初稿和长终稿都能保存，声音进入 `review`。
- 更新前端结构测试，要求终稿范围内不显示成功提示，超范围提醒包含偏差和非阻断文案。
- 先运行定向测试，确认新契约在实现前按预期失败。

## 任务 2：解除后端字数阻断

- 从声音生成主流程移除 `_fit_episode_word_count()` 调用。
- 删除不再被生产路径使用的私有自动修复方法和无用导入。
- 保留字数范围输入校验、任务快照和提示词变量。
- 保留历史 `episode_word_count_repair` 提示词定义，避免破坏旧记录。

## 任务 3：调整终稿审核提醒

- 终稿编辑器继续实时计算字数。
- 仅在有终稿内容且偏短或偏长时渲染提醒。
- 提醒展示当前值、目标范围和相差字数，并明确“仍可正常保存和审核”。
- 把人工编辑的“未保存/已保存”状态与字数提醒分开。
- 将警示样式从错误色改为普通警示色。

## 任务 4：更新产品文案与文档

- 把专辑生成卡中的“生成后自动验收”改为“终稿超范围时提醒”。
- 更新 README，说明范围仍进入提示词，但不再自动改写或导致失败。
- 保留提示词页面对字数目标和系统保护的说明，删除“字数修复”作为生产承诺的描述。

## 任务 5：回归验证

- 运行字数、工作流、批次和任务恢复相关后端定向测试。
- 运行后端全量测试。
- 运行前端 ESLint、生产构建和渲染结构测试。
- 运行 `git diff --check`，核对无密钥、运行数据或无关文件。
- 更新 Phase 39 记录并提交实现。
