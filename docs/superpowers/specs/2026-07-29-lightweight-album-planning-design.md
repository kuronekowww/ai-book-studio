# 轻量分层专辑规划设计

## 背景

当前专辑大纲任务把全书拆书稿、知识资产 ID 和段落级原文索引一次性输入模型，
并要求模型直接输出严格 JSON。以《当代中国社会分层》为例，25 章拆书稿经过
现有本地压缩后仍有 93,072 字符，完整专辑提示词约 94,574 字符，包含数百个
知识资产 ID 和原文索引。

真实测试表明：

- Kimi K3 最小连接请求约 5.97 秒成功；
- 同一专辑提示词只输入前三章、共 7,960 字符时，约 393.91 秒后成功返回
  3 集合法 JSON；
- 全书请求约 8 分钟后返回成功响应但没有文本内容；
- Claude Sonnet 5 的同类全书请求在 600 秒后被网关以 HTTP 504 终止。

问题不是网页鉴权或模型路由不可用，而是单次任务同时承担全书理解、专辑策划、
精细溯源和严格结构化，输入与输出负担超过当前网关的稳定处理范围。

## 目标

将专辑规划改造成可以持久恢复的分层任务：

1. 创作阶段只设计易读 Markdown 大纲，不输出严格 JSON；
2. 每集只选择一个或多个真实一级章节，不输出知识资产 ID 或段落索引；
3. 内容较多时按知识模块分批展开，并保存每个模块的中间结果；
4. 使用第二次小输入调用把已完成 Markdown 转成简单页面数据；
5. 在声音细纲生成前，再从已选一级章节中匹配具体知识资产和原文块；
6. 保留现有人工专辑大纲检查点、任务进度、失败重跑和版本追溯。

## 非目标

- 本轮不改变章节拆书、知识资产和段落级原文块的存储结构。
- 本轮不要求专辑大纲模型选择案例、论据或金句的知识资产 ID。
- 本轮不增加新的人工检查点。
- 本轮不修改已经确认或已经生产声音的历史专辑。
- 本轮不实现逐字流式输出。
- 本轮不取消声音生产阶段的段落级事实溯源。

## 核心原则

### 策划与溯源分离

专辑大纲回答“讲什么、按什么顺序讲、来自哪些大章节”。声音生产回答“本集具体
使用哪些观点、案例和原文块”。模型不再在一次请求中同时解决两个不同粒度的问题。

### 创作与格式分离

第一次调用负责内容策划，输出 Markdown；第二次调用只负责格式转换，输入是已经
完成的短 Markdown，不再输入拆书稿。格式失败不触发重新策划。

### 章节标识由程序控制

程序为每个已纳入拆书的一级章节生成稳定标识，例如：

```text
[CHAPTER_02] 第二章 中国社会分层结构的特征
[CHAPTER_03] 第三章 社会分层的四个实验
```

模型只能从输入目录中选择章节标识。每集至少选择一个标识，允许选择多个；同一
章节也允许被多集使用。

## 方案比较

### 方案 A：Markdown 创作 + 小模型格式转换（采用）

模型先生成 Markdown 专辑设计，再用第二次小输入调用转换成简单结构。优点是创作
自由度高、格式转换稳定、错误可以分阶段重试。额外增加一次轻量调用，但远小于
当前全书严格 JSON 请求。

### 方案 B：固定 Markdown + 程序解析

只调用一次模型，由程序使用标题和标签解析 Markdown。调用更少，但模型稍微改变
标题层级或标签文字就可能解析失败，恢复能力弱于方案 A。

### 方案 C：Markdown 人工确认后再转换

先让用户审核原始 Markdown，再转换为页面数据。最稳，但增加第三个人工检查点，
不符合首版只确认章节切分和专辑大纲的既定流程。

## 任务架构

### 阶段 1：准备章节策划目录

程序从最新成功的逐章拆书版本生成轻量章节目录。每个一级章节只包含：

- 稳定章节标识；
- 完整章节标题；
- 章节主题；
- 子主题标题；
- 必要的精简主要观点。

不包含知识资产 ID、段落级原文索引、完整论据或案例证据。全书模块规划优先使用
章节标题、章节主题和子主题目录；精简观点只在需要区分相似章节时补充。

### 阶段 2：设计全书知识模块

模型根据章节策划目录输出 Markdown 模块设计。每个模块包含：

- 模块标题；
- 模块要解决的听众问题；
- 认知顺序和承接关系；
- 来源章节标识；
- 建议声音数量。

模块设计不展开每集细节，不输出 JSON。

### 阶段 3：分模块展开 Markdown 专辑大纲

每个模块只读取其关联章节的精简拆书内容，并生成 3 至 5 集声音。模块最多两个
并行。单模块输入目标不超过 12,000 字符；超过时继续按相邻章节或子模块拆分，
不得静默截断。

单集 Markdown 格式为：

```markdown
## 第1集：声音标题
听众钩子：一句话说明为什么值得听。
核心主题：一句话说明本集解决的问题。
核心要点：
1. 第一条递进内容；
2. 第二条递进内容；
3. 第三条递进内容。
内容类型：解读
来源章节：[CHAPTER_02]、[CHAPTER_03]
```

模型不得输出知识资产 ID、段落索引或完整稿件。叙事类只使用“解读”；非叙事类
仅在确有承上启下需要时使用“过渡”。

### 阶段 4：合并与轻量格式转换

程序按模块顺序合并 Markdown，并将合并结果输入格式转换模型。转换结果只包含：

```json
{
  "album_outline": [
    {
      "title": "声音标题",
      "main_points": "听众钩子、核心主题和核心要点",
      "chapter_keys": ["CHAPTER_02", "CHAPTER_03"],
      "content_type": "解读"
    }
  ]
}
```

这是内部页面数据转换，不是创作调用。转换提示词由系统保护，不开放用户修改，
也不再读取拆书稿。

### 阶段 5：程序校验与保存

后端只校验：

- 标题、主要内容、内容类型和章节标识存在；
- 每个章节标识属于当前书籍并且已纳入拆书；
- 每集至少关联一个一级章节；
- 叙事类没有过渡声音；
- 用户填写期望集数时，实际数量差异会给出说明。

不再校验知识资产唯一性，不要求段落级索引，也不禁止同一一级章节用于多集。

## 数据结构

### 专辑规划草稿

新增持久规划产物，用于保存中间结果和恢复任务。建议使用独立表
`album_planning_artifacts`：

- `id`
- `run_id`
- `project_id`
- `artifact_type`：`module_plan`、`module_outline`、
  `combined_outline`、`structured_outline`
- `module_key`
- `position`
- `source_chapter_ids_json`
- `content`
- `status`
- `error_message`
- `created_at`
- `updated_at`

唯一约束以运行、产物类型和模块键为边界，支持重复启动时复用已完成模块。

### 声音记录

不新增专辑级精细来源字段，复用现有字段：

- `source_section_ids` 保存一个或多个一级章节 ID；
- `section_identifier` 保存可读的章节标识和完整标题；
- `knowledge_item_ids` 在专辑大纲阶段为空；
- `source_content_indexes` 在专辑大纲阶段为空。

现有 `episode_knowledge_items` 关系在后续“匹配本集原文”阶段再写入。

## 声音生产前的精细来源匹配

确认专辑大纲后，每条声音开始生成细纲前增加 `match_episode_sources` 阶段：

1. 读取声音标题、听众钩子、核心主题、核心要点和一级章节范围；
2. 收集这些章节下的概念、观点、论据、案例和金句目录；
3. 使用一次小范围选择调用匹配与本集直接相关的知识资产；
4. 后端校验资产确实属于所选一级章节；
5. 根据知识资产恢复有序段落索引和原文块；
6. 写入 `episode_knowledge_items`，再进入声音细纲生成。

来源选择只返回小型知识资产 ID 列表，属于声音生产的内部准备，不出现在专辑大纲
模型输出或人工大纲审核界面中。

如果没有匹配到可靠资产，声音任务停在 `match_episode_sources`，记录失败原因并
允许单条重跑；不得用模型常识或整章无差别文本继续生成。

## 提示词配置

现有“专辑大纲”可配置用户提示词改为控制 Markdown 创作，包括听众、选题、标题、
讲述风格和单集内容要求。受保护系统后缀改为 Markdown 格式和章节标识约束。

新增两个仅由程序维护的内部提示词：

- `album_module_plan`：设计全书知识模块；
- `album_outline_structure`：把合并 Markdown 转成简单结构。

声音来源匹配使用内部 `episode_source_match` 提示词。三个内部提示词不在用户提示词
标签页中单独显示，避免用户误删协议字段。

任务启动时继续锁定可配置专辑提示词版本和各阶段模型快照。内部格式提示词使用
系统版本号写入运行元数据。

## 运行状态与恢复

专辑规划顶层任务阶段调整为：

1. `prepare_chapter_catalog`
2. `design_album_modules`
3. `expand_album_modules`
4. `structure_album_outline`
5. `save_project_outline`

模块展开使用子运行记录。每个模块完成后立即保存 Markdown 并在运行记录中显示。
一个模块失败时，其他模块继续；重跑时只执行失败模块。页面刷新或应用重启后，
从已完成的模块和格式转换结果继续。

运行记录的阶段输出可以展开查看模块设计、单模块大纲和合并 Markdown，不显示
完整拆书稿或模型输入快照。

## 错误处理

- 章节目录为空：任务在准备阶段失败，提示先完成逐章拆书。
- 模块设计引用未知章节：模块设计失败，不进入展开阶段。
- 单模块输入超过上限：继续拆分，不截断。
- 单模块模型失败：保存其他成功模块，整体标记部分失败。
- Markdown 格式转换失败：保留完整 Markdown，只重试转换。
- 转换结果引用未知章节：保存转换草稿并在校验阶段失败。
- 声音来源匹配为空或越界：该声音失败，其他声音继续。
- 网关返回 504、空文本或截断：记录具体错误类型；允许从当前阶段重跑。

## 前端行为

专辑大纲审核页面继续使用现有卡片编辑器。每集“内容索引”改为“来源章节”，展示
一个或多个章节标签；不展示空的知识资产和原文索引区域。

任务进度卡展示模块总数、完成数和失败数。模块 Markdown 完成后可以立即展开，
即使最终格式转换尚未完成。

确认专辑大纲仍是唯一人工检查点。确认后进入生产页，由用户点击“生成全部终稿”。

## 兼容与迁移

- 已确认和已生成声音的项目不迁移、不改写。
- 旧的 `album_outline_draft_json` 继续保留用于历史失败诊断，新流程不再将其作为
  创作阶段主草稿。
- 已保存的提示词历史版本继续保留；系统默认升级为新的 Markdown 约束版本。
- 项目级专辑提示词覆盖继续生效，但保存时按新的必要占位符与 Markdown 保护规则
  校验。
- 现有思维导图生成逻辑不受影响，可继续复用已生成版本。

## 测试与验收

### 自动测试

- 章节策划目录只含允许字段且章节标识稳定；
- 多个一级章节可以映射到同一声音；
- 同一一级章节可以用于多条声音；
- 模块设计、模块展开、合并和格式转换可独立重跑；
- 模块输入超过上限时继续拆分且不丢章节；
- 格式转换不读取拆书稿；
- 未知章节标识被后端拒绝；
- 专辑保存时知识资产与段落索引为空；
- 声音生产前能匹配资产、恢复原文块并写入关系；
- 来源匹配失败只影响当前声音；
- 页面刷新和应用重启后复用已完成模块；
- 旧项目详情和三栏审核台继续正常工作。

### 真实验收

使用《当代中国社会分层》：

1. 输入全部 25 个已成功拆书的一级章节；
2. Kimi K3 完成模块设计和分模块 Markdown 大纲；
3. 创作阶段没有严格 JSON、知识资产 ID 或段落级索引；
4. 每集至少包含一个真实章节标识，部分声音包含多个章节；
5. 页面展示模块进度和 Markdown 中间结果；
6. 格式转换成功进入现有专辑大纲审核页；
7. 选择一集生成声音细纲，确认生产前自动匹配知识资产和原文块；
8. 单模块和单声音失败均可独立重跑。

## 成功标准

- 不再向专辑创作模型发送约 9.4 万字符并要求一次性输出严格 JSON；
- 大纲创作与数据格式转换完全分离；
- 专辑审核粒度为一级章节，支持一集对应多个章节；
- 精细来源匹配后移但不丢失段落级溯源；
- 长任务具备模块级进度、部分成功保存和重启恢复；
- 真实样书可以使用 Kimi K3 稳定生成并进入人工审核。
