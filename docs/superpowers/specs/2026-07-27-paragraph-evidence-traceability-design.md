# 段落级原文证据与知识资产溯源设计

## 背景与目标

当前拆书流程以标题节点作为 `content_index` 的来源。模型为一个子主题选择一个索引，该子主题下的概念、金句、观点、论据和案例共同继承该来源。声音组稿时，系统通过来源节点 ID 取回整个标题节点正文。

这种方式可以回溯到原书小节，但不能稳定回溯到支撑某一条知识资产的精确原文片段。对于正文较长的二、三级标题，来源可能覆盖数千字；同一子主题中的不同知识项也可能实际来自不同段落。

本次升级目标是：

- 保留“序言、第一章、第二章、附录”等原书章节结构和逐章模型调用边界；
- 在章节内部生成稳定、不可变、可版本化的段落级原文块；
- 每条概念、金句、观点、论据和案例独立关联一个或多个有序原文块；
- 严格校验需要保留原文的字段确实出现在所引用片段中；
- 专辑大纲按知识资产组织声音，而不是把一个段落索引等同于一条声音；
- 声音细纲、初稿和终稿能够确定性取回直接证据及必要上下文；
- 在网页和 Obsidian 中建立知识资产、原文片段与声音之间的双向链接；
- 保留旧拆书稿、旧知识资产和既有内容项目，不伪造旧数据的精确来源。

本设计不改变一级章节确认规则，不自动对整本旧书发起模型重跑，也不在首版实现跨书自动检索推荐。

## 核心概念

### 章节节点

`sections` 继续表达原书目录层级，包括一级章节及其二级、三级和更深标题。一级章节仍是章节审核、逐章拆书、失败隔离和单章重跑的边界。

标题节点的正文只包含该标题之后、下一个标题之前的文本；章节聚合仍按原书顺序遍历该一级章节的全部后代节点。

### 原文片段

原文片段是标题节点正文内部的细粒度证据单元。每个片段拥有独立 `content_index`，并记录：

- 所属书籍；
- 所属片段集版本；
- 所属一级章节；
- 来源标题节点 ID；
- 一级至当前节点的章节路径快照；
- 全书顺序和节点内顺序；
- 完整提取原文；
- 内容指纹；
- 当前或历史状态。

段落级 `content_index` 只负责证据定位，不决定专辑声音数量。

### 知识资产

概念、金句、观点、论据和案例继续保存为独立知识资产。每项资产通过结构化关联表引用一个或多个原文片段，来源顺序按原书顺序保存。

案例允许归纳；概念定义、金句、观点和论据仍属于需要保留原文表述的提取型资产。

## 原文层级与切分规则

### 两层结构

系统保留目录层级，并在每个标题节点正文内生成片段：

```text
第一章（一次模型调用）
├── 第一节
│   ├── content_a（段落级原文块）
│   └── content_b（段落级原文块）
└── 第二节
    ├── content_c（段落级原文块）
    └── content_d（段落级原文块）

第二章（另一次模型调用）
└── content_e
```

片段不得跨越标题节点或一级章节。二、三级标题继续出现在模型输入和片段路径中。

### 300–800 字语义段落块

切分以解析后的自然段为基础：

1. 保留自然段原顺序和文本，不进行摘要或改写；
2. 相邻短段依次合并，目标下限约 300 字；
3. 加入下一段会超过约 800 字时结束当前片段；
4. 单个超长段按中文或英文句末边界拆分；
5. 没有可用句末边界时才按安全字符位置拆分；
6. 节点末尾不足 300 字的尾块，若合并后不超过 800 字则并入前块，否则单独保留；
7. 空白节点不生成片段。

“300–800 字”是正常目标，不是以丢字、跨标题或改变顺序为代价的硬限制。服务端验证所有片段按规范化空白重新拼接后与节点原文一致。

EPUB 原文已经经过现有文本抽取和空白规范化；本设计保证相对于系统保存的提取正文无丢失，不承诺恢复 EPUB 内部不可见的字节级排版信息。

### 稳定索引

索引格式继续使用 `content_` 前缀，以兼容现有提示词和显示习惯。索引由以下内容确定性生成：

- 书籍 ID；
- 来源标题节点稳定 ID；
- 片段规范化原文的内容哈希；
- 同一节点内完全相同文本的重复序号。

原文不变时，重新构建得到相同索引；原文内容变化时生成新索引。索引不包含用户可编辑标题文本，避免单纯重命名标题导致证据键变化。

## 数据模型

### 原文片段集

新增 `source_fragment_sets`：

- `id`
- `book_id`
- `version`
- `content_fingerprint`
- `status`：`current` 或 `historical`
- `created_at`

同一本书最多有一个当前片段集。书籍当前全部已确认章节与正文的指纹不变时复用当前片段集；内容变化时，将旧集合标为历史并创建新版本。

### 原文片段

新增 `source_fragments`，保存可被多个片段集版本复用的不可变正文：

- `content_index`，主键；
- `book_id`；
- `source_section_id`，保存创建时的节点 ID；
- `text`；
- `text_fingerprint`；
- `created_at`。

新增 `source_fragment_set_members`，表达一个片段在某个书籍版本中的目录位置：

- `fragment_set_id`；
- `content_index`；
- `root_section_id`；
- `section_path_json`；
- `book_position`；
- `section_position`；
- 联合主键 `(fragment_set_id, content_index)`。

相同正文片段可被新旧片段集共同引用，因此书籍其他位置发生修改时，无须复制或改变未修改片段的 `content_index`。章节路径和顺序快照保存在片段集成员关系中。

`source_section_id` 是来源节点标识，不对片段使用删除级联；删除整本书时仍级联删除该书的片段集、成员和片段。

`chapter_analyses` 增加 `fragment_set_id`，明确该拆书版本使用了哪个原文片段集。

### 知识资产来源

新增 `knowledge_item_sources`：

- `knowledge_item_id`；
- `content_index`；
- `source_order`；
- 联合唯一约束 `(knowledge_item_id, content_index)`；
- 外键约束知识资产和原文片段存在。

`knowledge_items` 增加：

- `source_scheme`：`legacy_section_source` 或 `paragraph_fragment_source`；
- `status`：`active` 或 `superseded`；
- `stable_key`，用于识别不同拆书版本中的同一逻辑资产。

现有 `source_section_ids` 暂时保留作为兼容字段。对于新资产，它由关联片段所属标题节点确定性派生，不再是权威来源。

新增 `chapter_analysis_knowledge_items`，记录每个章节拆书版本包含哪些知识资产。现有 `chapter_analysis_id` 字段保留兼容读取，但新版本关系以关联表为准。

### 知识资产版本稳定性

新知识资产的 `stable_key` 根据书籍、资产类型、规范化正文和有序来源索引确定性生成：

- `knowledge_item_id` 一经生成永不改变；
- 同一章节重跑得到相同资产内容与相同来源时，复用原知识资产，并通过 `chapter_analysis_knowledge_items` 关联到新拆书版本；
- 文本或来源变化时生成新 ID；
- 旧资产不再物理删除，而是标记为 `superseded`；
- 新专辑只选择当前 `active` 且使用段落来源的资产；
- 已有内容项目继续引用创建时选择的资产，即使该资产后来被新版本取代，历史声音与版本仍可追溯。

### 声音与知识资产

新增 `episode_knowledge_items`：

- `episode_id`；
- `knowledge_item_id`；
- `position`；
- `role`：首版使用 `primary` 或 `transition_context`。

现有 `episodes.source_section_ids` 保留，由已选知识资产的片段来源自动派生。声音直接证据不重复持久化：服务端通过不可变的知识资产来源关联确定性计算。

## 章节拆书输入与输出

### 模型输入

逐章调用规则不变。每次输入一个已确认一级章节，以及其全部二、三级标题和正文片段。每个片段显式标注：

```text
[content_index: content_ab12]
[章节路径: 第一章 > 第二节]
原文……
```

同一片段只在一次章节输入中出现，按原书顺序排列。

### 模型输出

每项知识内容独立携带来源：

```json
{
  "chapter_title": "第一章",
  "chapter_theme": "章节主题",
  "subtopics": [
    {
      "title": "子主题",
      "definitions": [
        {
          "name": "概念",
          "definition": "定义原文",
          "source_content_indexes": ["content_ab12"]
        }
      ],
      "quotes": [
        {
          "text": "金句原文",
          "source_content_indexes": ["content_ab12"]
        }
      ],
      "viewpoints": [
        {
          "text": "观点原文",
          "source_content_indexes": ["content_ab12", "content_ab13"],
          "arguments": [
            {
              "text": "论据原文",
              "source_content_indexes": ["content_ab13"]
            }
          ],
          "case": {
            "summary": "案例概述",
            "relation": "案例与观点的关联",
            "source_content_indexes": ["content_ab14", "content_ab15"],
            "evidence_quotes": [
              {
                "text": "支持案例事实的原文摘录",
                "source_content_indexes": ["content_ab14"]
              }
            ]
          }
        }
      ]
    }
  ]
}
```

子主题本身不再拥有唯一来源索引。概念定义、金句、观点、每条论据和案例分别维护来源。

案例概述允许归纳，因此服务端不能仅通过字符串匹配证明整段概述的全部语义。为提高可审计性，案例必须同时输出至少一条 `evidence_quotes`；证据摘录执行严格原文匹配，页面同时展示概述、证据摘录和全部引用片段。

## 服务端校验

### 索引校验

每个 `source_content_indexes` 必须：

- 非空；
- 不重复；
- 存在于当前书籍的当前片段集；
- 属于本次模型调用的一级章节；
- 按原书顺序规范化保存。

未知索引、跨书索引、跨章节索引和空来源均拒绝。

### 原文匹配

服务端对下列内容执行确定性匹配：

- 概念定义；
- 金句；
- 观点；
- 每条论据；
- 案例的每条证据摘录。

匹配时只规范化连续空白和换行，不忽略标点，不进行同义改写，不使用模糊语义匹配。待校验文本必须完整出现在其有序来源片段拼接结果中。

案例的 `summary` 和 `relation` 不要求逐字出现，但必须引用至少一个片段并提供能够严格匹配的证据摘录。提示词明确禁止加入引用片段无法支持的事实。

### 事务边界

JSON 语法错误可继续使用现有语法修复提示词。语法修复不得改变文本或来源索引。

索引或原文匹配失败时不触发模型暗中改写；该章节拆书失败，并返回具体字段、文本摘要和错误索引。章节分析版本、知识资产和来源关联在同一个数据库事务中写入，任一校验或写入失败均不产生半份结果。

成功重跑后：

- 保存新的章节拆书版本；
- 将该章上一批当前知识资产标为 `superseded`；
- 插入或复用新资产；
- 建立每项资产的有序片段关联；
- 保留旧章节版本、旧资产和旧项目引用。

## 拆书稿展示

Markdown 不再只在子主题下显示一次内容索引。每项资产显示自己的来源：

```text
### 金句
- 金句原文
  - 来源：content_ab12

### 主要观点：观点原文
- 来源：content_ab12、content_ab13

**论据：**
- 论据原文
  - 来源：content_ab13

**案例故事：**
- 概述：……
- 来源：content_ab14、content_ab15
- 原文证据：……
```

压缩拆书稿必须保留知识资产 ID、全部来源索引和案例证据摘录。压缩后服务端验证资产 ID 与来源集合完全一致。

## 专辑大纲

### 输入

生成专辑大纲时，完整或压缩拆书稿向模型公开：

- 知识资产 ID；
- 资产类型；
- 资产正文；
- 来源章节；
- 来源片段索引；
- 书籍内容顺序。

只有 `active` 且 `source_scheme=paragraph_fragment_source` 的资产可进入新专辑。如果任一已纳入拆书的一级章节尚无精确溯源版本，系统阻止生成专辑大纲并列出待重跑章节，避免把未完成章节静默排除。

### 输出

每条普通声音输出：

- `title`
- `main_points`
- `knowledge_item_ids`
- `content_type`

后端校验知识资产存在、属于项目来源书籍并处于可用状态。一条普通声音可以包含多个知识资产；同一主知识资产首版不得被拆入多条普通声音。过渡声音可以引用前后声音资产作为 `transition_context`，但不能改变主资产归属或用来凑集数。

后端根据知识资产自动汇总并按原书顺序去重 `source_content_indexes`，再派生兼容的 `source_section_ids`。

专辑集数仍由用户的可选期望集数和特殊要求控制；段落片段数量不直接决定声音数量。

## 声音组稿上下文

### 直接证据

声音细纲输入包括：

- 书籍信息；
- 当前声音框架；
- 已选择知识资产及其类型；
- 每项资产的直接来源索引；
- 直接来源片段的完整原文。

多个来源按书籍、章节和片段顺序排列，保持多书项目可扩展性。

### 辅助上下文

对每组直接证据，服务端可附带同一标题节点内前后各一个当前片段集的相邻片段。辅助上下文：

- 与直接证据分区显示；
- 明确标记为“辅助理解，不是该知识资产的直接引用”；
- 去重后按原书顺序排列；
- 不写入知识资产的来源关联；
- 不改变声音的直接证据集合。

声音初稿和终稿继续带入同一知识资产、直接证据与辅助上下文，并在输入快照中保存完整内容。人工终稿版本继续保留模型原稿和来源快照。

## 网页交互

### 书籍工作台

- 继续显示一级至四级章节树和逐章状态；
- 增加“原文片段”统计；
- 旧章节显示“旧索引版本，需要重新拆书”；
- 精确版本显示知识资产数量和片段覆盖数量；
- 单章重跑继续可用，不自动触发整本书。

### 拆书结果

- 每条概念、金句、观点、论据和案例下显示来源索引标签；
- 点击标签按需请求片段详情，不在书籍详情接口一次性返回全书全部原文；
- 片段详情展示书名、完整章节路径、片段顺序和完整原文；
- 案例同时展示归纳内容和严格匹配的原文证据摘录。

### 专辑大纲审核

- 每条声音显示已选知识资产；
- 显示覆盖的直接原文片段数量；
- 可展开预览知识资产与原文证据；
- 用户调整声音顺序、标题和框架时保留资产关联；
- 首版不提供自由输入任意片段 ID，只允许选择当前有效知识资产。

### 三栏审核台

- 右侧证据栏按知识资产分组；
- 直接证据默认展开；
- 相邻辅助上下文默认折叠；
- 版本区继续展示生成模型、提示词版本和输入快照信息。

## API

现有书籍、章节拆书、专辑生成和声音生成接口保持路径兼容，响应增加证据状态和统计。

新增按需读取接口：

- `GET /api/source-fragments/{content_index}`：返回片段正文、章节路径、顺序和状态；
- `GET /api/knowledge-items/{knowledge_item_id}/sources`：返回知识资产的有序直接证据；
- `GET /api/episodes/{episode_id}/evidence`：按知识资产返回直接证据和辅助上下文。

所有接口通过数据库关系验证书籍和项目范围。浏览器不能提交任意本地文件路径或任意未登记的 `content_index`。

## Obsidian 双向链接

书籍 Vault 结构增加“原文片段”目录：

```text
01_书籍/
  某书/
    01_原文章节/
    02_原文片段/
    03_知识点/
    04_案例/
    05_金句/
```

每个片段笔记包含：

- `content_index`
- 章节路径和顺序；
- 完整原文；
- 引用它的知识资产链接；
- 引用它的声音链接。

每张知识卡包含有序片段链接；声音笔记包含知识资产链接和直接证据链接。系统继续只更新受控生成区块，保留用户个人批注区块。

旧知识卡继续输出旧来源小节 ID，并标记“旧索引版本”；不伪装为段落级双向链接。

## 旧数据迁移

数据库升级时：

1. 为现有书籍基于当前已确认章节生成当前片段集，不调用模型；
2. 保留所有旧章节拆书版本和知识资产；
3. 旧知识资产设置 `source_scheme=legacy_section_source`；
4. 不推断旧资产对应的精确片段；
5. 按章节计算精确溯源状态；
6. 书籍页面提示需要重跑的章节。

新旧章节版本可暂时并存，但生成新的专辑大纲前，所有纳入拆书的一级章节必须完成段落级精确拆书。既有项目和既有声音不被强制迁移，仍可查看、编辑和重跑其历史流程；若用户希望其使用精确证据，需要基于新资产重新生成专辑大纲。

## 错误处理

- 片段生成丢字、乱序或跨标题：停止构建，不改变当前片段集；
- 当前章节没有正文片段：章节拆书失败并提示检查章节范围；
- 模型引用未知或越界索引：整章失败；
- 提取型资产无法匹配原文：整章失败，显示具体资产；
- 案例没有来源或证据摘录：整章失败；
- 章节事务写入失败：回滚章节版本、资产和来源关系；
- 专辑引用失效或旧资产：拒绝专辑生成或保存；
- 片段详情引用历史片段：允许只读查看，并明确标记历史状态；
- Obsidian 同步单个文件失败：保留现有清单和人工批注，返回失败文件。

## 测试与验收

### 单元与迁移测试

- 章节结构保持不变；
- 片段不跨标题和一级章节；
- 短段合并、长段按句拆分、尾块处理符合规则；
- 片段规范化拼接无丢字、无重排；
- 相同输入生成相同索引；
- 修改正文生成新片段集，旧片段仍可读取；
- 旧 SQLite 幂等增加新表和字段；
- 旧知识资产被标为旧来源，不生成伪造关联。

### 拆书测试

- 每类资产独立携带来源数组；
- 多来源去重并恢复原书顺序；
- 未知、跨书、跨章节和空索引被拒绝；
- 概念定义、金句、观点、论据和案例证据摘录严格匹配；
- 匹配失败不产生章节版本或半份知识资产；
- 重跑相同结果复用稳定资产 ID；
- 变化结果保留旧资产，并使新资产成为当前版本；
- Markdown 在每项资产下显示来源。

### 下游测试

- 专辑按知识资产组合声音；
- 段落数量不影响期望声音数量；
- 未完成精确拆书的书籍不能生成新专辑；
- 声音直接证据由资产来源确定性汇总；
- 辅助上下文只来自同一标题节点的相邻片段；
- 三阶段输入使用同一直接证据集合；
- 旧项目继续可读，已有声音引用不失效。

### 页面与 Obsidian 测试

- 页面显示章节精确溯源状态和待重跑提示；
- 每项知识资产可打开片段详情；
- 专辑大纲展示资产和证据覆盖；
- 三栏审核台区分直接证据和辅助上下文；
- Obsidian 中片段、知识资产和声音链接双向一致；
- 重复同步幂等且保留人工批注。

### 真实最小验证

使用《当代中国社会分层》的一个较短一级章节：

1. 不自动重跑整本书；
2. 构建该章段落片段；
3. 执行一次单章拆书；
4. 检查至少一个观点、一个论据和一个案例或金句的独立来源；
5. 从知识资产点击索引读取精确原文；
6. 创建一个短测试声音，验证细纲输入包含直接证据和分区的辅助上下文；
7. 确认旧章节拆书版本仍可查看。

## 非目标

- 自动为旧知识资产猜测段落来源；
- 自动重跑整本旧书；
- 基于向量数据库自动推荐跨书知识资产；
- 在首版中允许用户输入任意未登记的来源索引；
- 证明模型归纳案例的全部语义绝对无误；系统提供严格证据摘录校验和人工可审计来源；
- 修改原书一级章节确认和最多 5 章并行规则。
