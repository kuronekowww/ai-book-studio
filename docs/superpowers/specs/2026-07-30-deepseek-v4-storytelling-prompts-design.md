# DeepSeek V4 故事化讲书提示词升级设计

## 1. 背景与目标

当前产品已经把思维导图、全书知识模块设计、分模块专辑大纲、声音细纲、声音初稿和
声音终稿接入统一的版本化提示词中心，并严格区分全书拆书稿、模块拆书稿和段落级原文。

本次升级的目标是：在不改变既有数据流、来源边界和结构校验的前提下，让专辑策划与
声音文稿更适合此前没有读过原书、主要通过连续收听获取知识的听众。最终稿应当有趣、
循序渐进、通俗易懂，保留原书精华，同时针对 DeepSeek V4 容易信息过载、清单化、
段落过长和重复总结的问题增加明确约束。

目标例文只作为叙事方法与听觉节奏参考，不复制其固定问候、口头禅、句式或具体内容。

## 2. 范围

本次修改以下六套提示词：

1. 思维导图；
2. 全书知识模块设计；
3. 分模块专辑大纲；
4. 声音细纲；
5. 声音初稿；
6. 声音终稿。

不修改数据库领域模型、输入占位符、模型选择界面、任务队列、模块集数算法、原文匹配
算法、字数算法或页面输出结构。初稿和终稿均按 DeepSeek V4 优化，但仍可被其他模型
正常调用。

## 3. 核心设计原则

### 3.1 分层约束

故事性必须从上游结构进入，不在终稿阶段临时添加。

- 全书知识模块负责全书覆盖和理解顺序；
- 分模块专辑大纲负责逐集选题与连续收听动力；
- 声音细纲负责可讲述的内容路线；
- 声音初稿负责生成完整、有画面、可听懂的正文；
- 声音终稿负责减法编辑、听感和准确性自检。

相同规则不在多个环节完整复制。每个环节只承担自己的决策，程序保护层保存跨环节
不可违反的事实、来源、数量和格式约束。

### 3.2 面向未读听众

所有策划环节都以“此前没有阅读过原书、将通过听书获取内容的人”为目标听众。模型
不能默认听众认识书中人物、概念、制度、事件背景或专业术语。

每集只回答一个中心问题，通常使用 2 至 4 个主要认知模块。附件中的“每 500 字交付
1 至 2 个核心观点”解释为听觉节奏：每 500 字推进 1 至 2 个理解步骤，不增加独立
中心观点数量。

### 3.3 轻松但克制

语言可以使用少量有画面的口语、自然问答和幽默反差，例如“死局”“更扎心”一类
表达，但不能连续使用夸张词、强塞网络梗或把情绪化描述当成事实结论。

幽默优先来自事实反差、人物选择、结果落差和听众熟悉的生活观察，而不是固定口头禅。
不得机械重复“想象一下”“这就像”“这象征着”等句式。

### 3.4 事实与故事素材边界

所有事实、人物、数据、案例、定义、动机和因果只能来自当前环节允许的输入材料。

- 不允许自行补充外部新闻、历史背景、真实人物或现实案例；
- 输入材料包含新闻或外部案例时，可以使用；
- 优先把原书案例、调查和数据还原为有起因、变化、结果和意义的微型故事；
- 原书没有案例时，可以使用明确标注为“假设”的生活化场景解释概念；
- 假设场景不得包含新的事实性结论、真实机构数据或未经原文支持的因果。

原文金句只在输入中确实存在、与本集主题直接相关且适合听觉场景时引用。没有合适金句
时直接总结核心价值，禁止为了升华编造或硬塞金句。

### 3.5 作者称呼

不反复使用“作者认为”“书中提到”。只有以下情况才提作者：

- 作者亲身经历；
- 需要区分作者观点与编辑解释；
- 直接引用原文；
- 不标明归属会造成事实误解。

同一篇文稿中对作者的称呼保持一致。

## 4. 六阶段职责与提示词调整

### 4.1 思维导图

输入保持为完整或压缩后的全书拆书稿。

提示词强调：

- 识别全书核心问题和内容性质；
- 按金字塔结构组织知识；
- 用因果、递进、并列或对照关系连接章节；
- 以未读听众的理解路径安排知识顺序；
- 第二层分支标明来源一级章节。

思维导图不负责声音标题、故事化口播或网络化表达，只输出简洁 Markdown 知识地图。

### 4.2 全书知识模块设计

输入保持为策划版全书拆书稿、轻量章节目录、用户专辑要求和目标集数范围。

该环节只输出知识模块，不生成逐集声音：

- 覆盖全部一级章节；
- 识别书籍类型和听众阅读目的；
- 每个模块解决一个明确的听众问题；
- 说明模块如何承接前后知识；
- 根据目标集数合理控制模块数量；
- 相邻且高度相关的章节可以合并；
- 保留原书主要叙述顺序，但听众理解顺序优先。

用户提供的“声音小节、吸睛标题和内容类型”要求不放在此环节，转入分模块专辑大纲。

### 4.3 分模块专辑大纲

输入保持为当前模块任务、当前模块详细拆书稿、全书章节目录、专辑要求和每集字数范围。

每集必须包含：

- 有具体吸引力的声音标题；
- 一句话听众钩子；
- 一个中心问题或核心主题；
- 2 至 4 个递进核心要点；
- 解读或过渡内容类型；
- 一个或多个来源一级章节。

选题优先从具体异常、冲突、人物选择、反常识结果、现实困惑或因果悬念切入。不得用
空泛宏大词语包装章节摘要，不机械地一章一集，不重复观点凑集数。

过渡声音不是必选项，只在两个大知识模块之间确实需要承上启下时使用。叙事类书籍仍以
解读声音为主。

### 4.4 声音细纲

输入严格保持为当前声音框架和所属模块拆书稿，不读取段落级原文、上一集终稿或外部
资料。

细纲结构包含：

1. 声音主题与唯一中心问题；
2. 听众最终应能复述的判断；
3. 可以直接进入正文的开篇预告；
4. 2 至 4 个递进正文部分；
5. 每部分的背景、主要观点、论据、故事抓手和字数预算；
6. 每两部分之间的一句过渡；
7. 回答开场问题的一两句结尾。

每个正文部分只承担一个主要认知任务。案例最多选择两个，优先选择能直接支撑核心观点
且具有起因、变化和结果的材料。超出目标篇幅的次要知识点明确舍弃，避免与专辑其他声音
重复。

细纲只有在当前声音框架已经明确包含前后集承接意图时，才标记需要回顾或预告的知识点；
它不生成上一集内容的具体回顾措辞。第一集不回顾，不强制固定开场和结尾。

### 4.5 声音初稿

输入保持为声音细纲、当前声音匹配到的段落级原文、项目字数范围和可用的上一集终稿。

内容优先级：

1. 声音细纲决定内容范围和逻辑顺序；
2. 段落级原文提供事实、数据、案例细节和准确表述；
3. 项目字数范围决定内容容量；
4. 原文中未进入细纲的材料不能因为存在于输入中就自动扩写进正文。

写作前由模型在内部完成篇幅分配，不输出分析过程。每集保持一个中心问题和 2 至 4 个
主要认知模块。开篇先建立具体问题，再给出本集认知地图。

非叙事类使用以下故事化路径：

> 现实现象或生活困惑 → 常识预期 → 反差结果 → 概念解释 → 原书证据 → 现实意义

叙事类使用以下故事化路径：

> 人物处境 → 目标或原文明确的动机 → 行动 → 结果 → 关键剧情意味着什么

专业概念按“日常说法—准确含义—具体例子或场景—现实意义”展开。数据后立即解释
“这意味着什么”，不连续堆叠年份、比例、政策或定义。

初稿只输出连续口播正文，不输出标题、小标题、序号、加粗、括号式写作说明或分析过程。

### 4.6 声音终稿

输入保持为声音初稿、当前声音匹配到的段落级原文、当前声音框架、项目字数范围和可用
的上一集终稿。

终稿只做减法编辑和听觉优化：

- 不重新选题；
- 不改变初稿逻辑顺序和中心判断；
- 不借原文输入增加初稿未覆盖的新知识点；
- 删除重复解释、论文腔、清单腔和无意义总结；
- 拆分过长句子和段落；
- 保留自然问答、必要的概念复现和故事推进；
- 让每次概念复现承担新的逻辑作用；
- 结尾回答开场问题，不过度升华；
- 只有内容自然递进时才保留下一集悬念。

终稿输出前在内部检查人物、数字、术语、定义、动机、事件顺序和因果是否与输入一致，
检查实际篇幅和段落衔接，但不输出检查过程。

## 5. DeepSeek V4 专项约束

声音初稿和声音终稿都针对 DeepSeek V4 增加以下明确规则：

- 不把原文目录逐项复述成文章；
- 不用“第一、第二、第三、综上所述”组织整篇；
- 不连续堆叠数据、定义和政策名称；
- 不换一种说法重复总结同一观点；
- 不擅自补充新闻、历史背景、现实案例或常识推断；
- 不为显得深刻而添加抽象升华；
- 不把全部原文信息压缩成高密度清单；
- 段落明显过长时主动拆分，每段只完成一个推进动作；
- 内容超出字数容量时删除次要论据，不牺牲可理解性；
- 最终只输出可逐字转成音频的连续正文。

这些规则与现有最多两次字数修复共同工作。模型首次输出仍超出项目范围时，程序继续按
实际偏差进行扩写或压缩；提示词本身负责减少触发修复的概率。

## 6. 书籍类型分流

运行时根据 `book_type` 在声音细纲、初稿和终稿的系统保护层追加不同要求。

### 6.1 叙事类

- 讲清人物关系、处境、目标、行动和事件后果；
- 人物动机和事件因果完全遵循输入材料；
- 不用常理推断填补原文没有解释的动机；
- 不为简化故事省略会影响理解的关键人物与背景；
- 讲解服务于关键剧情，不把故事改写成观点清单。

### 6.2 非叙事类

- 讲清问题、概念、机制、证据、数据含义和现实影响；
- 同样使用人物、场景、调查过程、案例变化和结果组织故事感；
- 没有原书故事时可以使用明确的假设场景；
- 假设场景只承担解释功能，不成为新的论据；
- 不把非叙事内容写成干燥的定义与论点罗列。

## 7. 连续专辑的衔接规则

上一集回顾和下一集预告均为可选。

- 第一集不回顾；
- 当前集不依赖上一集时不强行回顾；
- 细纲只依据当前声音框架标记承接意图，不推断或复述未传入的上一集内容；
- 初稿和终稿只有拿到可用的 `previous_episode_final` 时，才可以写具体的上一集回顾；
- 回顾只提与当前问题直接相关的一点，不复述上一集摘要；
- 下一集确实承接当前未解决问题，且当前声音框架已经提供相关方向时，才使用一句悬念；
- 没有自然承接关系时，结尾直接回答本集问题；
- 不固定使用“大家好，欢迎回来”或“我们下集见”。

## 8. 程序保护层

以下内容继续由程序控制，不开放给用户模板删除：

- 原文与来源边界；
- 一级章节和模块范围；
- 必要占位符；
- 专辑 Markdown 输出结构；
- 内部结构化转换；
- 模块集数校验和一次自动纠偏；
- 初稿与终稿字数验收和最多两次修复；
- 任务启动时的提示词版本锁定；
- 叙事类与非叙事类动态分流；
- 终稿不得新增初稿范围外事实。

用户提示词负责主要创作方法、听众定位、故事化路线和语言风格。

## 9. 版本发布

六个系统约束版本全部升级，并创建新的全局用户模板版本：

| 环节 | 当前全局版本 | 新全局版本 |
|---|---:|---:|
| 思维导图 | v1 | v2 |
| 全书知识模块设计 | v1 | v2 |
| 分模块专辑大纲 | v3 | v4 |
| 声音细纲 | v3 | v4 |
| 声音初稿 | v2 | v3 |
| 声音终稿 | v2 | v3 |

旧版本和项目覆盖全部保留。运行中的任务继续使用启动时锁定的旧版本；发布后新启动的
任务使用新的有效版本。

## 10. 错误与兼容处理

- 旧模板使用 `book_analysis`、`module_source` 或细纲 `source_text` 时继续兼容；
- 旧模板包含固定 1500 字要求时，项目字数范围继续由系统保护层覆盖；
- 旧模板要求外部新闻、自由发挥或终稿补充新内容时，新的系统来源边界优先；
- 项目覆盖不会被自动重写，用户可以在页面中恢复新全局版本或保存新的项目版本；
- 模板缺少必要材料占位符时继续在保存阶段阻止；
- 模型输出格式、数量或字数不合格时继续使用现有修复与失败记录机制。

## 11. 测试与验收

### 11.1 自动化测试

- 六个默认模板包含正确的输入占位符和职责文案；
- 必要占位符与旧版兼容别名校验不回退；
- 叙事类和非叙事类在细纲、初稿、终稿生成不同保护规则；
- 细纲上下文不包含段落级原文、人物关系资产或上一集终稿；
- 初稿上下文包含声音细纲和段落级原文；
- 终稿上下文包含声音初稿和同一来源范围的段落级原文；
- DeepSeek V4 防扩写、去清单化、故事化和内部自检规则进入最终提示词快照；
- 旧提示词锁、任务恢复和批量生产继续工作；
- 后端全量测试、前端结构测试、ESLint 和生产构建通过。

### 11.2 本地运行验收

- 在“提示词”页确认六个新全局版本和历史版本；
- 使用现有项目预览六个环节的真实输入；
- 确认细纲只显示声音框架与模块拆书稿；
- 确认初稿显示细纲与段落级原文；
- 确认终稿显示初稿与段落级原文；
- 确认系统保护区出现对应书籍类型和 DeepSeek V4 约束；
- 不在本次提示词发布中自动重跑现有声音或覆盖人工终稿。

## 12. 验收标准

实现完成后应满足：

1. 六个环节职责清楚且不存在重复生成逐集目录的冲突；
2. 非叙事类文稿也具有可感场景、反差和故事推进，不退化成观点清单；
3. 叙事类人物动机、事件顺序和因果不被自由发挥；
4. DeepSeek V4 不因看到大量原文而主动扩展细纲范围；
5. 2000–2500 字等项目范围内仍保持一个中心问题和 2 至 4 个主要模块；
6. 最终正文自然、口语化、轻松但克制，不包含视觉化结构；
7. 外部新闻、真实案例和数据不会在输入缺失时被编造；
8. 原文金句不被强行添加；
9. 旧提示词和项目覆盖可追溯、可恢复；
10. 所有自动化回归与本地预览通过。
