# 单集字数范围非阻断提醒设计

## 背景

当前项目把“每集目标字数”同时用作创作目标和任务成功条件。声音初稿、声音终稿生成后，后台会计算字数；超出范围时继续调用模型自动调整，最多两次，仍不合格便把当前阶段和声音任务标记为失败。

这会产生三个问题：

1. 模型已经生成了可审核的完整文稿，但因为篇幅偏差，用户看不到最终结果。
2. 自动改写会增加等待时间和模型调用成本，也可能破坏第一次生成时较好的表达。
3. 字数只是内容策划目标，不应覆盖用户对最终内容质量的人工判断。

## 已确认目标

1. 字数范围继续保留在项目配置和各阶段提示词中，作为模型的创作目标。
2. 初稿和终稿不再执行自动字数修复，也不再因字数不符合范围而失败。
3. 模型生成成功后，初稿和终稿原样保存，声音任务继续进入审核状态。
4. 审核台默认展示最新终稿。
5. 只有终稿低于或高于预期范围时，才在终稿编辑器下方显示非阻断提醒。
6. 字数提醒不影响人工保存、确认、批量生成、单条重跑和历史版本。

## 方案比较

### 方案 A：取消自动修复与失败判定，前端仅显示超范围提醒

后端直接保存初稿、终稿；前端按项目范围计算最新终稿或当前编辑内容的字数，仅在超范围时提示。

优点：

- 符合“字数是目标，不是门槛”的产品语义。
- 不增加额外模型调用。
- 模型原始结果可直接审核，不会被自动改写覆盖。
- 后端任务状态和前端展示保持一致。

缺点：

- 偏差较大的文稿需要用户人工判断是否重跑。

这是本次采用的方案。

### 方案 B：保留自动修复，但两次后仍保存并提醒

优点是部分文稿可能自动回到范围内；缺点是仍会增加成本和等待时间，且可能改变文风，不符合“最后不用强制校验”的直接诉求，因此不采用。

### 方案 C：只修改前端，忽略后台字数失败

后台仍会在保存终稿前抛错，页面无法取得最终产物，任务状态也会继续显示失败。该方案不能真正解决问题，因此不采用。

## 后端行为

### 保留

- `episode_word_count_min` 和 `episode_word_count_max` 项目字段。
- 创建专辑规划时对范围输入的合法性校验。
- 后台任务元数据中的锁定字数范围。
- `{{episode_word_count_range}}` 提示词变量及系统保护层中的创作目标。
- 字数统计纯函数，供前端规则测试和未来报告能力复用。

### 移除

- `generate_episode()` 在初稿和终稿生成后调用 `_fit_episode_word_count()` 的逻辑。
- 因生成内容低于或高于范围而抛出阶段错误的路径。
- 进度中“正在调整初稿/终稿字数”的二次模型调用。

`episode_word_count_repair` 内部提示词暂不从数据库或历史版本中删除，避免破坏旧任务快照和历史记录；生产工作流不再调用它。

### 状态语义

模型 API 调用成功并返回非空文稿后：

- 当前阶段产物正常保存；
- 阶段进度记为成功；
- 完成终稿后声音状态进入 `review`；
- 字数偏差不会写入任务错误，也不会让批量子任务失败。

模型调用、内容为空、数据库写入等真实错误仍按现有机制失败。

## 前端行为

终稿编辑器继续实时计算当前文本字数，并与项目的目标范围比较。

### 范围内

- 不显示字数状态或成功提示。
- 编辑器底部只保留与人工编辑相关的状态和操作。

### 偏短

在终稿编辑器下方显示：

> 字数提醒：当前 1760 字，低于预期 2000–2500 字，还差约 240 字。文稿仍可正常保存和审核。

### 偏长

在终稿编辑器下方显示：

> 字数提醒：当前 2860 字，高于预期 2000–2500 字，超出约 360 字。文稿仍可正常保存和审核。

提醒使用警示色但不使用错误态，不禁用任何按钮。人工修改文本时提醒实时更新；保存为新人工版本后仍按保存后的内容计算。

当还没有终稿或编辑器为空时，不显示字数提醒。

## 数据与兼容性

- 不新增数据库字段，不执行数据迁移。
- 已有项目继续使用原来的目标范围。
- 已经因字数失败的历史任务不会自动改写历史状态；用户重跑相应声音后，新工作流会直接保存模型结果。
- 旧的模型原稿、自动修复稿和人工版本都继续可回看。
- 运行中已经锁定配置的任务在服务更新后恢复时，仍携带字数范围用于提示词，但不再把它用于结果阻断。

## 测试

### 后端

1. 初稿明显短于范围时仍保存产物并继续生成终稿。
2. 终稿明显长于范围时仍保存产物，声音状态进入 `review`。
3. 初稿和终稿生成只调用各自模型一次，不调用 `episode_word_count_repair`。
4. 真实模型异常仍按原有阶段错误处理。
5. 字数范围继续出现在初稿和终稿提示词快照中。
6. 批量生成中，字数偏差不会增加失败数量。

### 前端

1. 没有终稿时不显示提醒。
2. 字数在范围内时不显示提醒。
3. 偏短时显示当前字数、目标范围和缺少字数。
4. 偏长时显示当前字数、目标范围和超出字数。
5. 提醒出现时，“重新口语化”和“保存修改”仍按原有条件可用。
6. 页面不再出现“生成后自动验收”等强制字数文案。

### 回归

- 每集最少/最多字数输入及合法性校验保持有效。
- 六阶段提示词配置与项目级覆盖保持有效。
- 单条重跑、批量并发、失败隔离和任务恢复保持有效。
- 前端 lint、生产构建和结构测试通过；后端全量测试通过。

## 验收标准

1. 一条终稿即使不在目标范围内，只要模型生成成功，任务就成功并默认展示该终稿。
2. 字数偏差不再触发自动模型改写或阶段失败。
3. 终稿范围内不显示字数提示；范围外显示准确、非阻断的字数提醒。
4. 用户可以照常编辑并保存范围外的终稿。
5. 项目配置和提示词中仍保留目标字数范围。
