# AI 讲书知识与文稿工作台设计规格

日期：2026-07-24  
状态：待用户书面审核  
项目代号：AI Book Studio

## 1. 背景与问题

现有讲书流程由多个 Dify 工作流和人工脚本串联，覆盖书籍切分、拆书稿、思维导图、专辑大纲、声音细纲、声音初稿和文本风格调整。流程本身已经积累了较完整的提示词与分支逻辑，但存在以下问题：

- 数据在工作流、CSV 和人工复制之间流转，来源关系容易丢失；
- 章节、小节、知识点、声音稿之间没有统一且稳定的标识；
- 某个任务失败后难以从指定节点恢复；
- 提示词、模型和结果缺少版本记录，单条重跑容易覆盖旧稿；
- “拆书”和“写稿”绑定过紧，无法自然扩展到一篇稿件融合多本书；
- 生成结果没有系统化沉淀到 Obsidian，难以长期复用。

本项目把这些 Dify 节点迁入一个本地优先的网页产品，先打通单本书闭环，同时在数据结构上支持未来的多书内容项目。

## 2. 产品目标

首版必须做到：

1. 上传 EPUB、TXT 或 Markdown 书籍；
2. 解析并人工确认章节切分；
3. 自动生成拆书稿、知识资产和全书思维导图；
4. 从一本已拆解书籍创建内容项目；
5. 自动生成并人工确认专辑大纲；
6. 批量生成声音细纲、初稿和终稿；
7. 任意声音可从指定阶段单条重跑，并保留历史版本；
8. 所有知识资产和文稿能按稳定结构同步到 Obsidian；
9. 关闭并重启服务后，项目、版本和未完成任务可以恢复。

### 2.1 非目标

首版不包含：

- PDF、扫描件 OCR 和复杂排版还原；
- 多人协作、账号系统、权限管理和在线支付；
- 云端部署与跨设备同步；
- Obsidian 笔记反向参与模型生成；
- 可视化拖拽式通用工作流编辑器；
- 正式支持多本书共同生成一篇稿件。

多书生成不进入首版验收，但底层数据模型和提示词路由不得把内容项目限制为“一项目只能绑定一本书”。

## 3. 核心边界：知识库与创作库分离

系统分为两个业务域。

### 3.1 知识库

知识库负责把原书加工为可重复利用且可追溯的知识资产：

- 书籍元数据；
- 章节、小节和原文；
- 子主题、概念、观点、论据、案例和金句；
- 全书思维导图与主题网络；
- 每项知识资产的来源小节。

知识库中的内容忠于原书。模型新增的解释、总结或推演必须与原书摘取内容分开标记。

### 3.2 创作库

创作库负责把知识资产组织为可发布内容：

- 内容项目；
- 项目来源包；
- 专辑大纲；
- 单条声音；
- 声音细纲、初稿和终稿；
- 生成版本与运行记录。

内容项目与书籍、知识资产之间使用多对多关系。首版界面限制一个项目只选择一本书，但数据库和服务接口允许以后选择多本书。

## 4. 用户流程

### 4.1 书籍入库与拆解

1. 用户上传 EPUB、TXT 或 Markdown。
2. 系统检测编码、换行、目录和标题层级，生成章节切分草案。
3. 用户在检查点一完成合并、拆分、改标题和层级调整。
4. 用户确认后，系统为书籍、章节和小节生成稳定 ID。
5. 系统按章节并行生成拆书稿。
6. 系统从拆书稿中结构化生成知识资产。
7. 系统生成全书思维导图。
8. 阶段结果写入数据库，并按设置增量同步到 Obsidian。

章节确认后，小节 ID 不因显示标题修改而改变。若用户重新切分原文，系统创建新的解析版本并提示其对下游引用的影响。

### 4.2 内容项目与专辑大纲

1. 用户从已完成拆解的书籍创建内容项目。
2. 系统构建项目来源包，包含书籍拆书稿、知识资产和思维导图。
3. 系统生成专辑大纲，每条声音包含：
   - 顺序；
   - 标题；
   - 3–6 条主要内容；
   - 来源知识资产与小节 ID；
   - 内容类型：解读、过渡或故事；
   - 风格类型：观点或鸡汤。
4. 用户在检查点二编辑、删除、排序并确认专辑大纲。
5. 确认后的声音进入批量生产队列。

### 4.3 声音生产

每条声音依次执行：

1. 声音细纲；
2. 声音初稿；
3. 口语化与风格精修，形成声音终稿。

不同声音可并行执行；同一声音内部保持顺序。过渡类声音使用前后知识模块的拆书稿；解读类声音使用实际引用的小节原文；故事类声音使用人物关系与事件信息。精修阶段可以读取前序声音粗纲，为开场增加自然承接。

用户可以：

- 查看当前输入、输出、模型和提示词版本；
- 编辑阶段输出并将人工版设为当前版本；
- 从细纲、初稿或精修节点重跑；
- 对比历史版本；
- 查看每项内容所引用的原文证据。

## 5. 《圆圈正义》标准验收样书

本地文件 `/Users/xmly/Downloads/拆书/圆圈正义.md` 作为首版端到端验收输入，原书不复制进项目、不提交 Git。

已识别的输入特征：

- 文件为 UTF-8 Markdown，约 37 万字节；
- 包含 8 个三级标题和 49 个四级标题；
- 存在 1,286 个字面量 `\n`；
- 正文集中在较少的超长物理行中；
- 包含大量 `[1]` 形式的脚注标记；
- 主题名和文章名可能重复。

导入器必须：

1. 将正文中的字面量 `\n` 恢复为真实段落；
2. 保留 Markdown 标题层级；
3. 识别“主题 → 文章 → 语义小节”三级结构；
4. 对超长文章进行语义小节切分，但保留文章父级；
5. 将脚注与所属文章共同保存；
6. 使用稳定 ID 解决重名标题冲突；
7. 不把正文引用或编号误识别为标题。

## 6. 系统架构

采用本地优先的前后端分离架构：

- 前端：React + TypeScript + Vite；
- 后端：FastAPI + Python；
- 数据库：SQLite；
- 文件存储：本地项目数据目录；
- 模型调用：后端统一的模型适配层；
- Obsidian：后端通过用户选择的 Vault 路径增量写入。

### 6.1 前端模块

- 书籍库；
- 章节切分检查器；
- 书籍知识工作台；
- 内容项目列表；
- 专辑大纲编辑器；
- 声音生产工作台；
- 运行记录与版本对比；
- 模型、提示词和 Obsidian 设置。

主要页面：

- `/library`
- `/library/books/:bookId`
- `/library/books/:bookId/segments`
- `/projects`
- `/projects/:projectId`
- `/projects/:projectId/episodes/:episodeId`
- `/runs`
- `/settings`

### 6.2 后端模块

后端按清晰边界拆分：

1. `ingestion`：文件校验、文本规范化、EPUB 解析；
2. `segmentation`：目录识别、章节树和语义切分；
3. `knowledge`：拆书稿、知识资产和思维导图；
4. `projects`：内容项目、来源包、专辑大纲和声音；
5. `workflows`：节点执行、状态机、队列和恢复；
6. `providers`：模型供应商适配、重试、超时和用量统计；
7. `prompts`：提示词模板、变量契约和版本；
8. `obsidian`：路径规划、Markdown 渲染和增量同步；
9. `versions`：输入快照、人工编辑版和模型生成版；
10. `api`：面向前端的稳定 HTTP 接口。

每个模块通过服务接口交互，不允许前端直接读取 SQLite 或模型供应商 API。

### 6.3 未来上云边界

首版不实现云端能力，但应保持以下替换点：

- SQLite 可替换为 PostgreSQL；
- 本地文件可替换为对象存储；
- 本地进程内队列可替换为分布式任务队列；
- 本机 Vault 写入可替换为导出包或 Obsidian 插件同步；
- 本地密钥存储可替换为托管密钥服务。

## 7. Dify 工作流迁移

现有 YAML 不作为运行时依赖，而作为迁移来源。迁移时保留其提示词、变量、分支和代码处理语义，并转换成项目内可测试的定义。

### 7.1 节点类型

首版支持四类节点：

- `llm`：模型调用；
- `code`：确定性文本处理与结构转换；
- `condition`：按内容类型、风格或前序内容分支；
- `map`：按章节或声音并行迭代。

原工作流中的 HTTP/RPC 节点用于获取远程书籍数据，首版由本地文件入库替代，不迁移为运行节点。

### 7.2 工作流映射

| 原工作流 | 项目内工作流 |
| --- | --- |
| 书籍长章节分段 | 文本规范化、长章节切分、分段分析、结果合并 |
| 叙事类自动拆书 | 按章节批量拆书、故事/非故事结构化 |
| 思维导图 | 全书拆书稿压缩、思维导图、专辑大纲 |
| 声音细纲 | 解读/过渡、故事/非故事分支和细纲生成 |
| 声音初稿 | 鸡汤/观点/过渡/故事分支，先构思后成稿 |
| 文本风格 | 观点/鸡汤/故事及有无前序内容的精修分支 |

迁移后的每个提示词必须声明：

- 模板 ID 和版本；
- 所需变量；
- 输出契约；
- 默认模型配置；
- 可接受的最大上下文；
- 失败后的修复策略。

### 7.3 模型配置

系统不依赖 Dify，直接调用模型供应商 API。模型适配层提供统一接口，支持按阶段配置供应商、模型、温度、超时和重试。

YAML 中现有的 Claude、Gemini、豆包、通义千问和 DeepSeek 配置作为迁移参考，不硬编码为不可更改的唯一模型。用户可以为每个阶段选择已配置模型；项目保存所用模型快照。

## 8. 数据模型

核心实体：

- `Book`
- `BookFile`
- `ParseVersion`
- `Section`
- `BookAnalysis`
- `KnowledgeItem`
- `KnowledgeSource`
- `MindMapVersion`
- `ContentProject`
- `ProjectSource`
- `AlbumOutlineVersion`
- `Episode`
- `EpisodeSource`
- `ArtifactVersion`
- `WorkflowRun`
- `NodeRun`
- `PromptTemplate`
- `ModelProfile`
- `ObsidianSync`

关键关系：

- 一本书有多个解析版本；
- 一个解析版本有多级小节；
- 一个知识资产可引用多个小节；
- 一个小节可支持多个知识资产；
- 一个内容项目可关联多本书和多个知识资产；
- 一条声音可引用多个知识资产；
- 每个声音阶段有多个不可覆盖的版本；
- 每次节点运行绑定输入快照、提示词版本和模型配置。

稳定 ID 使用随机或时间有序 UUID，不使用标题、数组下标或文件路径作为主键。标题和顺序可修改。

## 9. Obsidian 结构

SQLite 是运行、版本和关系的主数据；Obsidian 是可阅读、可检索和可链接的知识视图。

```text
AI讲书知识库/
├── 00_总览/
│   ├── 书籍索引.md
│   ├── 知识主题索引.md
│   └── 内容项目索引.md
├── 01_书籍/
│   └── 圆圈正义__<book-id>/
│       ├── 00_书籍主页.md
│       ├── 01_原文小节/
│       ├── 02_知识点/
│       ├── 03_案例/
│       ├── 04_金句/
│       └── 05_思维导图.md
├── 02_内容项目/
│   └── <项目名>__<project-id>/
│       ├── 00_项目主页.md
│       ├── 01_来源包.md
│       ├── 02_专辑大纲.md
│       └── 03_声音/
│           └── <序号_声音名>/
│               ├── 声音细纲.md
│               ├── 声音初稿.md
│               └── 声音终稿.md
└── 99_同步清单/
    └── sync-manifest.json
```

每篇笔记包含 YAML 属性：

- `id`
- `type`
- `book_id`
- `source_section_ids`
- `project_id`
- `episode_id`
- `status`
- `tags`
- `created_at`
- `updated_at`

文件名使用可读标题并附稳定短 ID。正文使用 Obsidian 双向链接。同步采用清单与内容哈希，重复执行不创建重复笔记。系统生成区块可更新；用户个人批注保存在明确标记的保留区块中，重新同步不得覆盖。

## 10. 运行状态、错误处理与恢复

工作流和节点状态包括：

- `pending`
- `running`
- `waiting_for_review`
- `succeeded`
- `failed`
- `cancelled`
- `superseded`

要求：

- 拆书按章节运行，声音按单集运行；
- 单个任务失败不阻塞同批其他任务；
- 失败节点可自动重试，也可人工从该节点继续；
- 服务重启后从数据库恢复未完成任务；
- 模型超时、限流和临时网络错误使用有上限的指数退避；
- 结构化输出校验失败时自动修复一次，仍失败则转人工编辑；
- 大纲代码块或结构未闭合时不得自动进入下游；
- 用户取消只影响尚未完成的节点，不删除已生成版本；
- 同一节点的重复请求使用幂等键避免双重运行。

## 11. 安全与隐私

- 原书、数据库和生成稿默认只保存在本机；
- 原书测试文件不进入 Git；
- API Key 不写入数据库、日志、Obsidian 或前端持久化状态；
- 日志对请求头、密钥和大段原文进行脱敏；
- 后端只允许访问用户明确选择的导入文件和 Vault 路径；
- 书籍内容发送给模型前，界面明确显示所选供应商；
- 删除书籍或项目属于需确认操作，并优先采用可恢复的软删除。

## 14. 已确认的产品决策

- 首版输入：EPUB、TXT、Markdown；
- 首版形态：本地优先网页产品；
- 架构：React + FastAPI + SQLite；
- 模型调用：产品内直接编排，不依赖 Dify；
- 人工检查点：章节切分、专辑大纲；
- Obsidian：结构化沉淀，不读取旧笔记参与生成；
- 知识库与创作库分离；
- 首版打通单书闭环，底层预留多书项目；
- 《圆圈正义》作为标准验收样书。
