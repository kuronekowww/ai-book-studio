# 专辑全部声音终稿一键导出设计

## 背景

声音终稿目前只能在三栏审核台逐集查看和编辑。Obsidian 同步能够把每集稿件写入 Vault，但它面向知识库沉淀，会生成目录、前置信息、知识资产链接和多个文件，不能替代用户需要的“一键导出整张专辑终稿文本”。

用户需要在专辑审核台直接下载一份可继续编辑、复制或交付的 Markdown 文档。

## 已确认目标

1. 一键导出当前专辑下全部声音的终稿。
2. 导出为单个 Markdown 文件。
3. 严格按照专辑声音顺序排列。
4. 每集使用最新终稿版本；最新人工编辑版本自然优先于旧的模型版本。
5. 没有终稿或生成失败的声音保留原顺序位置，并标注“本集终稿尚未生成”。
6. 导出内容保持干净，不包含模型、提示词、知识资产或任务状态等审核元数据。
7. 导出是只读即时操作，不创建后台任务、不写入数据库、不在本地项目目录留下文件。

## 方案比较

### 方案 A：后端组装 Markdown，前端直接下载

后端使用一次查询获取专辑声音及每集最新终稿，统一完成排序、缺稿占位和 Markdown 渲染；前端请求完成后创建浏览器下载。

优点：

- 最新版本选择和排序规则只有一个权威实现。
- 不随声音数量增加前端请求次数。
- 可以直接测试完整导出文件。
- 以后扩展 TXT、DOCX 或 ZIP 时能复用后端导出数据。

这是本次采用的方案。

### 方案 B：前端逐集请求并合并

需要先读取项目，再为每条声音请求详情。声音较多时请求数量大，任一请求失败都可能产生不完整文件，且版本选择逻辑会落在前端，因此不采用。

### 方案 C：后端生成实体文件后返回路径

会引入文件命名冲突、清理和覆盖规则。当前下载内容可以即时生成，没有落盘需求，因此不采用。

## 导出接口

新增只读接口：

```text
GET /api/projects/{project_id}/finals/export
```

成功响应：

- `Content-Type: text/markdown; charset=utf-8`
- `Content-Disposition: attachment`
- 响应体为完整 Markdown 文本。

文件名语义为：

```text
{专辑名称}_全部终稿.md
```

前端使用当前项目名称生成下载文件名，并替换 `/ \ : * ? " < > |` 等不适合文件名的字符。若项目名称清理后为空，使用 `讲书专辑_全部终稿.md`。

项目不存在时返回 404。项目存在但尚无任何声音时仍返回一份只有专辑标题和说明的 Markdown 文件，不把正常的空专辑视为接口错误。

## 最新终稿选择

查询范围为当前项目下全部 `episodes`，按：

1. `episodes.position` 升序；
2. 相同位置时按声音 ID 确定性排序。

每集只取：

```text
artifact_versions.stage = 'final'
ORDER BY artifact_versions.version DESC
LIMIT 1
```

人工保存会创建新的终稿版本号，因此“最新版本”已经能够表达“有人工修改时导出人工版本；否则导出模型版本”，不需要额外的作者类型优先级。

导出时不要求声音状态为 `review` 或 `approved`。只要存在终稿版本就导出，避免历史任务状态与实际产物不一致时丢失内容。

## Markdown 格式

有声音的专辑：

```markdown
# 专辑名称

## 第 01 集：声音标题

最终文稿正文……

## 第 02 集：声音标题

> 本集终稿尚未生成
```

规则：

- 集数宽度至少两位，1–9 显示为 `01`–`09`；超过两位时不截断。
- 专辑名称和声音标题中的 Markdown 换行折叠为空格，避免破坏标题结构。
- 终稿正文只去除首尾空白，内部段落和 Markdown 原样保留。
- 每集之间使用两个换行分隔。
- 文件以换行结尾。

没有声音的专辑：

```markdown
# 专辑名称

> 当前专辑尚未创建声音。
```

## 前端交互

在声音目录上方的批量生产卡中，把操作区调整为：

- `生成全部终稿`
- `导出全部终稿`

导出按钮：

- 项目存在即可使用；没有声音时也允许导出空专辑说明。
- 批量生产运行中仍可导出当前已完成的版本，未完成项显示缺稿占位。
- 点击后显示现有全局忙碌提示“正在导出全部终稿…”。
- 请求成功后使用 `Blob` 和临时对象 URL 触发下载，随后释放 URL。
- 下载完成显示“已导出全部终稿”。
- 接口失败沿用页面现有错误提示，不生成空文件。

导出不会改变当前选择的声音、未保存的编辑器内容或任务进度。

### 未保存人工修改

导出只读取已经保存到数据库的最新终稿版本。若当前终稿编辑器有尚未点击“保存修改”的内容，导出按钮点击前进行确认：

> 当前终稿还有未保存修改，导出文件将使用最近一次已保存版本。是否继续？

用户取消时不发请求。这样可以避免静默丢失当前编辑内容，也不把单集临时文本混入后端导出的权威版本。

## 安全与兼容性

- 导出内容只来自当前项目及其声音，不接受用户传入 SQL、路径或模板。
- Markdown 在内存中生成，不把专辑名称作为服务器文件路径。
- 不包含提示词快照、模型配置、原文证据或 API 密钥。
- 不修改数据库结构。
- 已有项目、人工版本和模型版本无需迁移。
- 中文文件名由浏览器本地生成，避免跨浏览器解析 `Content-Disposition` 编码差异。

## 测试

### 后端

1. 项目不存在返回 404。
2. 按声音位置输出，不按创建时间或标题排序。
3. 每集只输出最高版本终稿。
4. 最新人工版本覆盖旧模型终稿。
5. 没有终稿的声音输出占位，不跳过。
6. 初稿或细纲不能误入导出。
7. 标题换行被折叠，终稿内部段落保持不变。
8. 空专辑输出明确说明。
9. 响应类型为 `text/markdown; charset=utf-8`。

### 前端

1. 批量生产卡显示“导出全部终稿”按钮。
2. 请求目标为项目级导出接口。
3. 使用 `Blob`、对象 URL 和下载属性触发单文件下载。
4. 文件名使用专辑名称并清理非法字符。
5. 当前终稿有未保存修改时先确认。
6. 导出不受批量任务运行状态限制。

### 回归

- 生成全部终稿、单条重跑和人工保存保持原行为。
- 终稿字数非阻断提醒保持有效。
- 后端全量测试、前端 lint、生产构建和渲染结构测试通过。

## 验收标准

1. 在任一内容项目审核台点击一次即可下载 `{专辑名称}_全部终稿.md`。
2. 文件中的声音顺序与网页目录一致。
3. 每集正文等于该声音最近一次已保存的终稿。
4. 缺稿声音保留标题和占位说明。
5. 导出不会修改项目、版本、任务或当前编辑内容。
