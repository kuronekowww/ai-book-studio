# 单条声音上下文链设计规格

日期：2026-07-27

## 目标

让单条声音的三个生产阶段始终同时获得“上一步产物”和该声音绑定的完整原文块，避免模型在失去原文证据的情况下继续加工。声音细纲还必须获得经过用户审核的当前声音内容框架；叙事类书籍额外获得与当前原文块精确关联的人物关系。

本次设计不改变“单条声音内部三阶段串行、不同声音最多并行五条”的既有生产规则。

## 核心原则

1. 原文块 ID 是各阶段取数的唯一依据，标题不作为关联键。
2. 每个阶段都重新从数据库读取绑定的完整原文，不依赖上一次请求中的临时字符串。
3. 上一步产物与原文证据使用明确分区，禁止把原文误当作上一步产物。
4. 人物关系只用于叙事类书籍，而且只读取与当前声音原文块关联的知识资产。
5. 非叙事类提示词完全移除人物关系、剧情和事件范围等叙事限定。
6. 不静默截断原文；供应商拒绝超长输入时明确失败，并允许用户调整来源块后重跑。

## 数据模型

### 书籍类型

在 `books` 表增加：

- `book_type TEXT NOT NULL DEFAULT 'non_narrative'`

允许值：

- `narrative`：叙事类
- `non_narrative`：非叙事类

上传书籍时必须选择类型。既有书籍迁移为 `non_narrative`，并允许用户在书籍知识页修改类型后重新拆书。

### 声音内容框架

在 `episodes` 表增加：

- `content_framework TEXT NOT NULL DEFAULT ''`

该字段保存专辑大纲中当前声音的主要内容、事件范围与讲述顺序。它与标题、内容类型、风格和来源块一起接受人工审核。

### 人物关系知识资产

复用 `knowledge_items` 表，不新增人物关系专表：

- `kind = '人物关系'`
- `body` 保存模型提取的结构化人物关系文本
- `source_section_ids` 保存产生该关系的原文块 ID

一个人物关系资产可以关联多个原文块，但声音生成只能选择与当前声音来源 ID 有交集的资产。

## 书籍上传与拆书

### 上传

上传表单新增书籍类型选择，默认展示“非叙事类”，但要求用户明确确认。书籍详情显示当前类型，并允许在重新拆书前修改。

### 非叙事类

沿用观点、案例和金句等现有知识资产流程，不请求人物关系，也不创建空人物关系资产。

### 叙事类

人物关系提取并入每个原文块的拆书模型输出，不增加声音生产阶段。模型输出必须包含：

- 人物名称
- 人物之间可由当前原文确认的关系

禁止根据常识、书外资料或其他未关联章节补充关系。

原文块 ID 不交给模型生成，而是由拆书服务根据当前输入块写入
`source_section_ids`，避免模型返回错误或虚构的 ID。

拆书过程中，每个原文块独立记录结果。部分原文块失败时：

- 保留已成功写入的知识资产；
- 记录失败原文块；
- 书籍不进入“拆书完成”状态；
- 用户可以重新执行失败块；
- 重新执行使用原文块 ID 幂等替换该块的模型知识资产，不产生重复人物关系。

## 专辑大纲审核

每条声音展示并允许编辑：

- 标题
- 内容类型
- 风格
- 多行声音内容框架
- 关联原文块

确认专辑大纲前逐条校验：

- `content_framework` 去除空白后不能为空；
- 至少关联一个有效原文块；
- 所有关联原文块必须属于项目引用的书籍。

校验失败时保留用户编辑内容，并定位到具体声音，不改变项目确认状态。

## 阶段上下文组装

新增独立的阶段上下文组装器。它只负责查询、校验和格式化输入，不负责调用模型或保存产物。

### 声音细纲

输入由以下部分组成：

1. 书名和作者；
2. 当前声音标题、类型和风格；
3. 用户确认的 `content_framework`，原样传入；
4. 叙事类当前来源块对应的人物关系；
5. 按原书顺序排列的完整原文块，每块带稳定 ID 和标题。

叙事类当前来源块没有提取到人物关系时，人物关系区写明“当前关联原文块未识别到人物关系”，不得读取其他块补齐。

### 声音初稿

输入由以下部分组成：

1. 书名和作者；
2. 最新声音细纲；
3. 与细纲阶段相同的完整原文块。

声音内容框架不重复作为独立输入，因为它已经被细纲吸收。模型仍必须以原文块为事实边界。

### 声音终稿

输入由以下部分组成：

1. 书名和作者；
2. 最新声音初稿；
3. 与前两个阶段相同的完整原文块。

终稿只能做口语化、结构和表达优化，不得借原文块增加初稿未覆盖的新事实段落。

### 重跑

- 从细纲重跑：重新读取声音框架、人物关系和原文块，随后顺序生成初稿与终稿。
- 从初稿重跑：读取最新细纲和当前原文块，随后生成终稿。
- 从终稿重跑：读取最新初稿和当前原文块。
- 修改来源块或声音框架后，旧产物继续保留；新产物保存为新版本。

## 提示词

### 叙事类声音细纲

将用户提供的提示词迁为正式模板，保留角色、任务、大纲框架、事实边界和文本输出格式。Dify 节点变量替换为项目内部字段：

- `booktitle` → 书名
- `author` → 作者
- `character` → 当前来源块人物关系
- `outline` → 当前声音内容框架
- `events` → 当前声音绑定的完整原文块

模板中所有系统要求也必须合并到 Anthropic 的 user 消息，以适配 DeepGate。

### 非叙事类声音细纲

使用独立模板，保留声音主题、开篇、过渡、正文论点、案例、结尾和事实边界，移除：

- 人物关系区；
- 剧情推进要求；
- 只适用于事件和人物的 `events` 限定。

### 初稿与终稿

两个模板都使用明确标签分隔：

- `# 上一步产物`
- `# 原文证据`

初稿要求以细纲为结构、以原文为事实依据。终稿要求保留初稿事实范围，只做适听化处理。三个提示词都升级版本号，旧版本产物保持可回看。

## 错误处理

以下情况在调用模型前失败：

- 声音内容框架为空；
- 没有关联原文块；
- 原文块不存在或不属于项目书籍；
- 从初稿或终稿开始重跑时缺少上一步产物；

单条声音失败时记录失败阶段和可读错误，专辑批次继续生产其他声音。修复数据后可以从失败阶段单条重跑。

模型返回空内容或非法结构时，不写入正式产物或知识资产。供应商拒绝超长输入时，保留完整输入边界信息并提示用户减少关联来源块，不自动截断原文。

## 前后端接口

### 书籍

- 上传接口增加 `book_type`。
- 书籍详情返回 `book_type`。
- 增加更新书籍类型的接口，仅在重新拆书前使用。

### 专辑大纲

- `EpisodeUpdate` 增加 `content_framework`。
- 项目详情和专辑大纲更新接口读写该字段。
- 后端承担最终确认校验，前端提供即时提示。

### 生成

现有单条重跑和批量生成接口保持不变。上下文组装发生在后端，因此前端不传原文正文、人物关系或上一步产物。

## 测试与验收

### 后端测试

1. 既有数据库迁移后书籍类型为非叙事类、声音框架为空。
2. 上传和修改书籍类型只接受两个允许值。
3. 专辑大纲缺少框架或来源块时无法确认。
4. 叙事类拆书人物关系按来源块 ID 保存和幂等替换。
5. 非叙事类拆书不产生人物关系资产。
6. 细纲请求包含框架、完整原文和仅匹配来源块的人物关系。
7. 非叙事类细纲请求完全不含人物关系区。
8. 初稿请求包含最新细纲和相同原文块。
9. 终稿请求包含最新初稿和相同原文块。
10. 从初稿、终稿重跑时缺少上一步产物会在模型调用前失败。
11. 单条失败不阻断最多五条并行的项目批次。

### 前端测试

1. 上传表单显示书籍类型选择。
2. 专辑大纲卡片显示多行声音框架。
3. 空框架时确认按钮给出具体错误。
4. 三栏审核台继续正确显示细纲、初稿、终稿和来源证据。

### 样例验收

- 使用《圆圈正义》作为非叙事类样例，确认声音细纲输入不含人物关系。
- 使用包含人物关系和剧情的短叙事样例，确认人物关系只进入引用对应原文块的声音。
- 对同一条声音分别从细纲、初稿和终稿重跑，检查每次输入都包含正确上一步产物和同一组完整原文块。

## 安全与兼容

- 原文正文、人物关系和模型输入只在本地后端处理，不进入浏览器存储或 Git。
- API 密钥继续只从 Git 忽略的本机 `.env` 读取。
- 数据库迁移使用带默认值的新增列，保持既有项目可打开。
- 现有人工终稿版本、批次失败隔离和 Obsidian 同步规则保持不变。

## 非目标

- 本次不实现多书融合声音的跨书上下文排序。
- 本次不增加向量检索或自动扩展未绑定原文块。
- 本次不改变模型供应商配置和 DeepGate 协议。
- 本次不增加声音生产阶段；人物关系只在拆书阶段产生。
