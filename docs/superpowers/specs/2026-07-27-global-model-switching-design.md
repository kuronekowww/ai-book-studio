# 全局模型切换设计

## 背景与目标

知声工坊当前通过 `.env` 在后端启动时固定一个模型，设置页只能展示当前模型。首版需要在不重启服务的情况下，从产品设置页全局切换模型，同时保证：

- 当前已配置的 Claude Sonnet 4.6 继续作为默认模型；
- 新增 6 个 DeepGate Anthropic Messages 模型预设；
- 切换只影响切换后启动的新任务；
- 已启动任务在整个生命周期内继续使用启动时锁定的模型；
- 历史产物始终记录实际使用的供应商和模型；
- API Key 仍只从本机环境变量读取，不进入数据库、浏览器、日志或 Git。

本设计只实现全局模型切换，不实现按书籍、项目、工作流阶段或单条声音分别选模型。

## 模型预设

后端维护不可由浏览器任意改写的模型预设表。预设包括现有模型和以下新增模型：

| 模型 ID | 模型名称 | Base URL |
| --- | --- | --- |
| `claude-sonnet-4-6-wangsu-anthropic` | `claude-sonnet-4-6-wangsu-anthropic` | 沿用当前本机配置 |
| `kimi-k3` | `kimi-k3` | `http://deepgate.ximalaya.local/kimi-k3-universal/api/v1` |
| `claude-sonnet-5` | `claude-sonnet-5` | `http://deepgate.ximalaya.local/claude-5-sonnet-universal/api` |
| `glm-5.2` | `glm-5.2` | `http://deepgate.ximalaya.local/glm-5.2-universal/api/v1` |
| `kimi-k2.6` | `kimi-k2.6` | `http://deepgate.ximalaya.local/kimi-k2.6-anthropic/api` |
| `deepseek-v4-pro` | `deepseek-v4-pro` | `http://deepgate.ximalaya.local/deepseek-v4-pro-anthropic/api` |
| `hy3` | `hy3` | `http://deepgate.ximalaya.local/hy3-universal/api/v1` |

所有新增预设使用现有 Anthropic Messages 协议和同一个本机 API Key。预设表不包含密钥。

为避免迁移时意外改变现有行为，首次升级后优先使用本地已保存的模型选择；如果尚未保存，则使用 `.env` 中当前模型；若环境变量不能匹配任何预设，则保留为只读的“环境变量模型”，直到用户主动切换到预设。

## 后端架构

### 模型目录

新增独立模型目录模块，负责：

- 定义允许选择的模型 ID、显示名称、供应商和 Base URL；
- 根据模型 ID 返回不可变的模型配置；
- 拒绝未知模型 ID；
- 构造对应的 Anthropic provider。

前端不能提交任意 Base URL、provider 或 model 字符串，只能提交后端公开的模型 ID。这可以避免设置接口成为任意内网请求入口。

### 全局选择存储

全局选择只保存一个模型 ID，持久化到应用本地数据目录中的设置文件。写入采用临时文件加原子替换，防止进程中断留下半份配置。

启动时加载规则：

1. 使用有效的本地已保存模型 ID；
2. 否则尝试匹配 `.env` 中的当前模型；
3. 否则沿用 `.env` 构造的现有 provider。

切换接口只有在目标 ID 存在且 provider 能成功构造时才替换当前选择。失败时保留原选择。

### 任务级模型快照

后端维护可切换的“当前 provider”，但工作流不在每个生成节点重新读取它。每次启动以下顶层任务时，先捕获一次不可变 provider 快照：

- 一本书的章节拆书批次；
- 单章拆书重跑；
- 思维导图与专辑大纲生成；
- 全部声音终稿批量生产；
- 单条声音或指定节点重跑。

该任务及其所有子步骤都显式使用同一快照。例如声音批次中的细纲、初稿、终稿，以及 JSON 修复调用，均不得在中途切换模型。

设置页切换模型时，不取消、不修改已运行任务；下一次新建任务才捕获新 provider。

### Anthropic Messages 地址规范化

Messages 端点按 Base URL 结构生成：

- Base URL 以 `/v1` 结尾：追加 `/messages`；
- 其他 Base URL：追加 `/v1/messages`。

拼接前移除末尾 `/`。因此：

- `.../api/v1` 生成 `.../api/v1/messages`；
- `.../api` 生成 `.../api/v1/messages`。

请求继续使用 `x-api-key`、`anthropic-version` 和现有 `trust_env=False` 策略。错误消息不得包含 API Key。

## API

扩展 `GET /api/settings/status`，返回：

- 当前 provider 和 model；
- 当前模型 ID；
- API Key 是否已配置；
- 数据目录；
- 可选模型列表；
- 当前选择来源（本地选择或环境变量）。

新增 `PUT /api/settings/model`：

```json
{
  "model_id": "kimi-k3"
}
```

成功时返回更新后的完整设置状态。未知 ID 返回 `400`；写入或构造失败返回明确错误，并保持原全局选择。

接口不返回 API Key 和完整鉴权头。

## 前端交互

设置页“模型调用”区域改为全局模型选择卡片：

- 展示当前模型和“全局生效”说明；
- 用单选列表或下拉框展示 7 个模型；
- 当前模型带明确选中状态；
- 用户选择新模型后点击“设为全局模型”；
- 保存期间禁用重复提交；
- 成功后立即刷新当前模型状态；
- 提示“新任务将使用该模型，运行中的任务不受影响”；
- 失败时保留原选项并展示后端错误。

API Key 继续仅显示“已通过环境变量配置”或“未配置”，不提供前端编辑或回显。

## 数据与追溯

不修改现有产物版本的 provider/model 字段含义。每次保存章节拆书稿、思维导图、声音细纲、初稿或终稿时，写入任务快照中的真实 provider 和 model。

本次不回写历史记录，也不把全局选择复制到书籍或项目记录。用户切换模型后重跑会自然产生带新模型信息的新版本，旧版本保持不变。

## 错误与边界

- 未配置 API Key：允许切换并保存模型，但启动真实生成任务时沿用现有“未配置密钥”错误。
- 未知模型 ID：拒绝请求，不改变当前模型。
- 本地设置文件损坏：忽略损坏内容并回退到 `.env`，设置状态返回可理解的来源信息。
- 切换期间有运行任务：运行任务继续使用原快照。
- 服务重启：恢复上次有效的全局选择。
- Base URL 不可达：设置本身仍可保存；真实任务发起请求时记录连接失败，避免切换动作产生额外计费探测。

## 测试与验收

后端测试覆盖：

- 7 个预设均可枚举且 ID 唯一；
- `/api/v1` 与 `/api` 两类地址都生成正确 Messages URL；
- 有效选择持久化并在重启式重建后恢复；
- 未知 ID 和损坏设置文件安全回退；
- 切换后新任务使用新模型；
- 切换前已启动的多阶段任务始终使用原模型；
- 产物版本记录任务实际模型；
- 状态接口不泄露密钥。

前端测试覆盖：

- 设置页显示全部模型和当前选中项；
- 保存时禁用重复提交；
- 成功切换后刷新显示；
- 失败后保留原模型并展示错误；
- 页面明确说明运行中任务不受切换影响。

人工验收流程：

1. 启动应用，确认默认仍为现有 Claude Sonnet 4.6；
2. 在设置页切换到一个新增模型，无需重启；
3. 启动一条短任务，确认版本记录新增模型；
4. 启动一个多阶段任务后切换模型，确认该任务的所有阶段仍记录原模型；
5. 再启动新任务，确认使用切换后的模型；
6. 重启服务，确认全局选择恢复。

## 非目标

- 按书、项目、阶段或声音选择模型；
- 在网页中编辑 Base URL、模型名称或 API Key；
- 自动测速、健康检查或模型能力排行；
- 自动故障转移到其他模型；
- 对已生成产物批量改写模型标记。
