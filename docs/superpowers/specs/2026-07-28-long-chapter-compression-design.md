# 长章节拆书稿分段压缩设计

## 背景

《当代中国社会分层》的完整拆书稿超过全书直接输入阈值，生成专辑大纲前会逐章压缩。当前实现把每个一级章节的完整拆书稿交给模型一次性压缩。部分章节超过一万字符，`doubao-seed-2.0-pro` 在约 6300 字符处以 `finish_reason=length` 截断，导致生成大纲接口返回 500，项目保持零条声音。

## 目标

- 长章节压缩不再因单次输出上限导致整个专辑生成失败。
- 每个 `content_index` 和 `knowledge_item_id` 在压缩前后完整一致。
- 任何分段失败时不缓存半成品。
- 已成功缓存的章节继续复用，避免重复模型调用。
- 后端返回可读的 400 错误，不再把模型生成问题暴露为 500。

## 方案

### Markdown 分段

先按空行分隔的 Markdown 内容块切分，在不超过目标字符数的前提下顺序合并。超长单块按行切分；仍超长时才按字符安全切分。分段严格保持原始顺序，不修改文本和来源标识。

目标输入长度为 5000 字符。该值明显低于本次触发截断的章节长度，同时能够让模型在保留全部知识资产和来源标识的前提下完成输出。

### 自动拆小重试

每段调用现有 `chapter_compression` 提示词。若 provider 抛出 `ModelOutputTruncatedError`：

1. 将当前段按 Markdown 边界二分；
2. 分别压缩两个子段；
3. 子段仍截断时继续递归；
4. 达到最小段长度仍截断时，返回包含章节标题的可读失败信息。

只对明确的输出截断自动拆分；网关错误、超时和其他模型错误直接返回，不进行无意义重试。

### 来源完整性

每个叶子段分别比较压缩前后的：

- `content_index`
- `knowledge_item_id`

两类标识的集合必须完全一致。所有叶子段成功后，再对合并结果与整章原稿做一次全量比较。任何缺失、新增或改写都会阻止缓存。

### 缓存与错误

整章所有分段成功并通过校验后，才写入 `chapter_analyses.compressed_markdown`。生成专辑接口捕获 `ModelGenerationError`，以 HTTP 400 返回可读原因，页面沿用现有错误提示展示。

## 验收

- 模拟长输入在单次压缩会截断时，工作流自动分段并成功合并。
- 合并结果保留全部来源标识，顺序不乱。
- 某段缺少来源标识时，整章不写缓存并返回明确错误。
- 已缓存章节不重复压缩。
- 模型生成错误通过生成专辑接口返回 400。
- 后端测试、前端测试、lint 和生产构建通过。
- “专辑 1”使用《当代中国社会分层》真实生成出非空专辑大纲。
