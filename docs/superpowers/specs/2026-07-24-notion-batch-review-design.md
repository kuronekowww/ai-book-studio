# 知声工坊：Notion 风格与批量终稿审核设计

日期：2026-07-24  
状态：已通过对话确认，待书面规格复核

## 1. 目标

本次迭代解决两个核心问题：

1. 将网页从偏展示型的工作台改为 Notion 式文档产品，降低视觉噪声并提高长文本阅读与编辑效率。
2. 在专辑大纲确认后，支持用户主动启动整张专辑的批量生产；单条声音内部依次生成声音细纲、声音初稿和口语化终稿，多条声音之间最多并行 5 条。

声音终稿是用户主要审核和编辑的内容。声音细纲与初稿降为辅助材料，默认折叠，但保留查看、版本回溯和指定阶段重跑能力。

## 2. 已确认决策

- 专辑大纲确认后不自动调用模型，只进入“等待生产”状态。
- 用户在生产页点击“生成全部终稿”后才创建批次。
- 单条声音严格按“声音细纲 → 声音初稿 → 口语化调整”顺序生产。
- 不同声音可以并行，首版并发上限固定为 5。
- 单条失败时记录错误并继续其他声音；批次结束后统一展示失败项。
- 失败声音支持从失败阶段单条重跑。
- 人工编辑终稿后点击“保存修改”，新增人工编辑版本，不覆盖模型原稿。
- 内容项目采用用户选定的“三栏审核台”。

## 3. 视觉系统

### 3.1 设计语言

产品界面采用 Notion 工作区风格，而非 Notion 官网营销页风格：

- 画布使用暖白 `#ffffff`，侧栏使用浅灰 `#f6f5f4`；
- 主文字使用暖黑 `#37352f`，次要文字使用 `#787671`；
- 分隔线使用 `#e5e3df`，主要依赖边界和留白建立层级；
- 主操作使用紫色 `#5645d4`，按压态使用 `#4534b3`；
- 成功、警告和错误分别使用 `#1aae39`、`#dd5b00`、`#e03131`；
- 按钮使用 8px 圆角，内容卡片使用 12px 圆角，状态徽章才使用胶囊形；
- 去除大面积深色面板、厚重阴影和衬线标题；
- 字体使用 `Notion Sans, Inter, -apple-system, system-ui, "Segoe UI", sans-serif` 回退栈；
- 正文默认 16px、1.55 行高，终稿编辑器使用 16px 至 17px、1.8 行高。

紫色仅用于当前最重要的操作，例如“生成全部终稿”和“保存修改”；文本链接继续使用蓝色或中性文字，避免主次混淆。

### 3.2 全局结构

- 左侧应用导航保留，但改为 Notion 式浅灰侧栏；
- 顶栏弱化为面包屑、页面标题和全局状态；
- 页面内容使用更宽的工作区，内容项目不再受窄卡片容器限制；
- 表单、列表和设置页统一使用平面文档块与 1px 边界。

## 4. 内容项目三栏审核台

### 4.1 左栏：专辑目录与批次

桌面端宽度约 300px，包含：

- 项目标题和项目状态；
- “生成全部终稿”主按钮；
- 批次进度：总数、完成数、失败数、当前并行数；
- 总进度条；
- 按专辑顺序排列的声音目录；
- 每条声音的阶段状态：排队中、生成细纲、生成初稿、口语化调整、待审核、已确认、失败；
- 失败项突出显示错误阶段，并提供单条重跑入口。

选择声音后，中栏和右栏切换到该声音。已完成声音保留在原目录位置，不因状态重新排序。

### 4.2 中栏：终稿主编辑区

中栏占据可用空间的主体，最低目标宽度为 640px。结构如下：

1. 声音标题、内容类型、表达风格和当前状态；
2. 声音细纲折叠块，默认关闭；
3. 声音初稿折叠块，默认关闭；
4. 放大的声音终稿编辑器；
5. 字数、当前版本和未保存状态；
6. “保存修改”主按钮；
7. “重新口语化”“从初稿重跑”等次级操作。

细纲和初稿展开后显示最新版本、模型信息和版本切换，但不会挤压终稿成为三列等宽卡片。

终稿编辑器加载当前选中的最新版本。用户修改后页面显示“未保存”。点击“保存修改”创建新的人工编辑版本，成功后更新当前版本号并清除未保存状态。

切换声音前若存在未保存内容，界面提示用户保存或放弃，防止编辑丢失。

### 4.3 右栏：证据与版本

桌面端宽度约 280px，包含两个折叠区域：

- 原文证据：引用章节、原文摘录、稳定来源 ID；
- 版本记录：模型版本和人工编辑版本，显示版本号、创建时间、生成模型或“人工编辑”标记。

选择历史版本时默认只读。用户可执行“以此版本作为新编辑起点”，不会覆盖历史版本。

### 4.4 响应式

- 大于等于 1180px：完整三栏；
- 860px 至 1179px：左栏保留，中栏扩展，右栏变为抽屉；
- 小于 860px：单栏，声音目录和证据均通过抽屉访问；
- 所有情况下终稿编辑器始终是页面最大内容区域；
- 按钮和折叠块的触摸目标不小于 40px。

## 5. 批量生产设计

### 5.1 触发条件

仅当项目已确认专辑大纲并处于“等待生产”“部分失败”或“待审核”状态时显示“生成全部终稿”。

点击按钮后：

1. 后端查找尚无终稿且未在运行的声音；
2. 如果没有待生成声音，返回可理解的提示，不创建空批次；
3. 创建一个专辑级批次记录；
4. 为所有待生成声音创建子任务；
5. 使用并发池同时处理最多 5 条声音。

已有终稿的声音默认跳过，避免重复调用模型。用户仍可进入单条声音主动重新生成。

### 5.2 单条执行链

每条声音的任务链固定为：

```text
声音细纲 → 声音初稿 → 口语化终稿
```

每个阶段完成后立即保存产物版本和运行状态，再进入下一阶段。若进程中断，恢复时从缺失的最早阶段继续，不重复覆盖已有版本。

“口语化调整”沿用 `final` 产物类型，对用户显示为“声音终稿”。现有文本风格工作流作为该阶段的迁移来源，不再显示为独立的第四步。

### 5.3 并发与恢复

- 使用服务端任务协调器和并发信号量，固定上限为 5；
- 并发限制作用于声音任务，而非单个模型阶段；
- 每条声音获得一个并发槽后，连续完成三个阶段再释放；
- 网页刷新、关闭或网络中断不会终止后端批次；
- 应用重启后将 `pending` 和中断的 `running` 子任务恢复为可继续执行状态；
- 同一项目同一时间只允许一个活动批次，重复点击返回现有批次。

### 5.4 状态

项目状态：

- `outline_review`：待确认专辑大纲；
- `ready`：等待生产；
- `producing`：批量生产中；
- `review`：全部可审核；
- `partial_failed`：批次完成但存在失败声音。

声音状态：

- `ready`
- `queued`
- `generating_outline`
- `generating_draft`
- `generating_final`
- `review`
- `approved`
- `failed`

批次状态：

- `pending`
- `running`
- `succeeded`
- `partial_failed`
- `failed`
- `cancelled`

失败记录必须包含失败阶段和可展示的错误消息，不写入 API Key、完整请求头或敏感环境变量。

## 6. 数据与接口

### 6.1 数据变化

在现有 `workflow_runs` 基础上增加父子关系和批次定位能力：

- `parent_run_id`：子任务所属批次；
- `error_stage`：失败阶段；
- `position`：声音在专辑中的顺序；
- `metadata_json`：非敏感进度摘要。

`artifact_versions` 增加：

- `author_type`：`model` 或 `human`，历史数据默认为 `model`。

应用启动时以幂等方式检查并补齐 SQLite 字段，保留已有本地数据。

### 6.2 新增接口

- `POST /api/projects/{project_id}/generate-all`
  - 创建或返回当前活动批次；
  - 返回批次和子任务摘要。
- `GET /api/projects/{project_id}/batch`
  - 返回最新批次、总进度、各声音状态和失败信息。
- `POST /api/episodes/{episode_id}/final-versions`
  - 请求体包含用户编辑后的终稿内容；
  - 创建 `author_type=human` 的新终稿版本。

现有单条生成接口继续用于“整条重新生成”和“从指定阶段重跑”。批次和单条任务共同遵守去重规则，防止同一声音被同时生成两次。

## 7. 错误处理

- 单条声音失败只结束对应子任务，不取消其他声音；
- 批次协调器使用隔离执行，汇总所有子任务结果；
- 失败声音在左栏显示失败阶段和“从失败处重跑”；
- 批次结束时，如果存在失败项，项目进入 `partial_failed`；
- 人工版本保存失败时保留编辑器中的未保存内容并允许重试；
- API 错误在界面显示用户可理解的中文信息；
- 取消批次时，不再启动排队任务；正在执行的阶段完成当前安全写入后停止进入下一阶段。

## 8. 验证

### 8.1 后端测试

- 同一条声音的三个阶段严格顺序执行；
- 六条及以上声音时，同时活跃的声音任务不超过 5；
- 一条声音失败后其余声音继续；
- 批次汇总能区分全部成功和部分失败；
- 已存在终稿的声音被跳过；
- 重复点击不会创建第二个活动批次；
- 应用重启后待运行任务可恢复；
- 人工保存创建新版本且模型原稿保持不变；
- 数据库字段升级不破坏已有数据。

### 8.2 前端验证

- Notion 风格变量在全站一致使用；
- 三栏布局在桌面视口成立；
- 中等和移动视口按设计折叠；
- 细纲和初稿默认折叠；
- 终稿可编辑，存在未保存提示；
- 保存后出现新的人工版本；
- 批次进度、并行状态、失败状态和重跑入口正确刷新；
- 已完成声音不会在“生成全部终稿”中被重复生成。

## 9. 验收标准

使用现有《圆圈正义》项目验收：

1. 确认专辑大纲后进入等待生产页；
2. 点击“生成全部终稿”，12 条声音进入任务队列；
3. 观察到最多 5 条声音同时处于生成阶段；
4. 每条声音依次产生细纲、初稿和口语化终稿；
5. 批次完成后目录显示成功数和失败数；
6. 打开任意声音时，终稿占据主要编辑空间，细纲和初稿默认折叠；
7. 修改终稿并保存后出现人工编辑新版本，模型原稿仍可查看；
8. 模拟单条失败后，其他声音继续完成，失败项能够单条重跑；
9. 页面刷新后批次进度和编辑版本仍然存在。

## 10. 本次不做

- 动态调整并发上限；
- 跨设备协同编辑和冲突合并；
- 自动语音合成；
- 多用户审批流；
- 自动删除模型历史版本；
- 云端部署与托管。
