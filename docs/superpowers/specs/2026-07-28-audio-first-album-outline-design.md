# 面向未读听众的专辑大纲生成设计

## 背景

现有专辑大纲已经具备问题导向、标题吸引力、知识资产与原文索引约束，但仍需进一步明确听众前提和有声内容的组稿方式：默认听众此前没有读过原书，需要仅通过连续收听理解全书。

本次优化聚焦专辑大纲生成提示词与结果校验，不改变项目数据结构，不增加额外模型调用。

## 目标

1. 每集面向没有读过原书的听众，不能依赖未解释的书内上下文。
2. 全专辑形成循序渐进的认知路线，而不是章节摘要的机械排列。
3. 每集以具体问题、事件、人物、矛盾或反常识现象作为内容入口。
4. 语言轻松但克制，兼顾故事性、信息密度与可信度。
5. 保留原书的核心知识、关键论证和内容顺序，并继续绑定知识资产与原文索引。
6. 继续使用项目保存的专辑大纲模型；未覆盖时，新项目默认使用 Kimi K3。

## 非目标

- 不直接模仿特定创作者的口头禅、标志性句式或个人表达。
- 不增加第二次标题润色或大纲改写模型调用。
- 不为了制造悬念而虚构事实、夸张结论或改变作者观点。
- 不新增必须由用户填写的字段。
- 不改变现有专辑大纲 JSON 数据结构。

## 方案选择

### 方案一：只补充风格描述

仅在提示词中加入“有趣、通俗、循序渐进”等要求。改动最小，但这些词语过于抽象，模型容易继续输出概括式、目录式大纲。

### 方案二：增加听众契约、组稿步骤与基础校验

在一次生成中明确未读听众前提、全专辑认知路线、单集选题入口、轻松克制的表达边界，并保留现有结构校验。成本不变，约束具体，适合首版。

### 方案三：生成后再调用模型进行编辑

先生成知识型大纲，再由第二个模型改写标题和叙事结构。风格控制更强，但调用成本、等待时间和索引漂移风险都会增加。

采用方案二：单次模型生成，加明确的编辑规则和轻量确定性校验。

## 听众契约

提示词必须把以下前提作为全局约束：

- 听众此前没有阅读过原书；
- 听众将主要通过音频连续获取本书内容；
- 不假设听众认识书中人物、概念、机构、时代背景或前文结论；
- 每集既要能独立回答一个问题，又要能够自然承接相邻声音；
- 陌生信息应提供理解本集所需的最低限度解释，避免百科式旁逸斜出。

## 全专辑编排

模型在输出前完成内部规划，但不输出分析过程：

1. 从完整拆书稿中识别全书的核心问题、关键背景、主要机制或事件线和最终启示。
2. 设计听众的认知路线，优先采用“建立背景或发现异常—提出问题—解释原因与机制—展开影响—回到现实或总结出路”的递进关系。
3. 根据知识模块的实际关系组合单集，不强制一章对应一集，也不能把无关内容硬凑在一起。
4. 检查前一集是否为后一集提供了必要背景，避免突然出现未解释的术语、人物或结论。
5. 将每集绑定到实际采用的知识资产与原文内容索引。

用户填写的期望集数和专辑特殊要求继续生效。用户没有填写集数时，由模型根据内容密度、知识模块和单集完整度自行判断。

## 单集选题规则

每集只解决一个清晰的核心问题或带来一个主要认知收获。选题优先从以下入口中选择最符合原书内容的一种：

- 一个反常识或异常现象；
- 一个具体人物或关键事件；
- 两种力量、利益或观念之间的冲突；
- 一个听众容易产生的疑问或误解；
- 一个隐藏在日常现象背后的机制；
- 一个与普通人生活相关的真实影响。

不允许把“第一章概述”“某某理论介绍”“核心内容解读”这类目录名称直接当作选题。相邻声音不能反复使用同一种标题句式或重复解释同一观点。

## 叙事与语言风格

用户希望参考高信息密度历史故事类视频的讲述体验。实现时只提取高层表达特征：

- 用具体情境、人物、事件或矛盾带出抽象知识；
- 因果链清楚，让听众知道事情为何发生、如何发展、造成什么影响；
- 信息密度高，但第一次出现的陌生概念必须解释；
- 可以使用适度反差、轻微调侃或冷幽默缓解理解压力；
- 幽默只服务于理解，不嘲弄真实人物和群体，不冲淡严肃主题；
- 不复制任何特定创作者的口头禅、标志性句式、段子或个人叙述声音。

风格强度采用“轻松但克制”：标题和内容可以有悬念与反差，但禁止堆梗、网络热词滥用、夸张标题党和脱离拆书稿的戏剧化加工。

## 输出结构

保持现有 JSON 字段：

```json
{
  "title": "声音标题",
  "main_points": "听众钩子：……\n核心主题：……\n核心要点：1. ……；2. ……；3. ……",
  "section_identifier": "章节与子主题说明，包含原文索引",
  "knowledge_item_ids": ["knowledge_xxx"],
  "content_type": "解读类"
}
```

字段规则：

- `title`：具体、准确、有收听吸引力；优先体现问题、冲突、人物、事件、反差或因果悬念。
- `main_points`：
  - `听众钩子`用一句话说明这件事为何值得听或它与听众已有认知的冲突；
  - `核心主题`用一句话说明本集最终要讲清的问题；
  - `核心要点`使用二至四个递进要点，优先形成“现象或故事—原因或机制—影响或启示”的逻辑链；
  - 不在字段中写完整文稿，不使用空泛宣传语。
- `section_identifier`：保留人类可读的章节、子主题说明以及精确 `content_index`。
- `knowledge_item_ids`：仅列出本集实际采用的知识资产。
- `content_type`：不强制生成过渡声音，只有跨越大型知识模块且确有必要时才使用“过渡类”。

## 来源与真实性

1. 思维导图和专辑大纲的内容输入仍然是全部成功章节合并后的拆书稿，不是全书原文。
2. 如果拆书稿超过模型输入预算，使用既有的拆书稿压缩流程，压缩结果必须保留知识资产 ID、`content_index`、章节层级和核心观点。
3. 标题、听众钩子、核心主题和核心要点都必须能够由拆书稿支持。
4. 不把模型的推断包装成原书观点，不引入拆书稿之外的人物、案例、数据或结论。
5. 后端继续依据知识资产来源校正原文索引。

## 约束优先级

提示词按以下优先级处理要求：

1. 内容真实且能够追溯到拆书稿；
2. 用户填写的专辑特殊要求；
3. 用户填写的期望集数；
4. 未读听众和有声理解要求；
5. 本设计的选题、递进与轻松克制风格；
6. 模型自行判断的组稿细节。

特殊要求可以改变侧重点、集数或表达方向，但不能取消真实性和溯源约束。

## 校验与错误处理

- 沿用现有 JSON 解析、知识资产和内容索引校验。
- 每集必须包含非空标题、听众钩子、核心主题、核心要点、知识资产和原文索引。
- `核心要点`少于两个时视为结构不完整。
- 不对标题“是否有趣”做主观程序评分，避免误杀有效结果；通过提示词、示例和人工审核控制质量。
- 结构不完整时保留失败原因并支持重跑，不覆盖用户已经确认的旧版本。

## 测试

### 提示词测试

- 明确听众没有读过原书，并通过音频获取内容。
- 包含全专辑认知路线和相邻声音承接规则。
- 包含单集问题导向、故事入口、因果链和轻松克制的表达要求。
- 明确不得复制特定创作者的口头禅和标志性表达。
- 保留集数、特殊要求、知识资产和原文索引约束。

### 结构测试

- 每集 `main_points` 包含听众钩子、核心主题和二至四个核心要点。
- 知识资产和内容索引能够回溯到合并后的拆书稿。
- 过渡声音不是必选项。
- 用户指定集数和特殊要求能原样传入。

### 回归测试

- 项目级专辑大纲模型选择继续生效。
- 未覆盖的新项目默认使用 Kimi K3。
- 已有专辑大纲不会因提示词升级而自动改写。
- 后端测试、前端测试、静态检查和生产构建通过。

## 验收标准

1. 新生成的专辑大纲明确服务于未读听众，不依赖未解释的书内上下文。
2. 全专辑具有可理解的认知递进，相邻声音之间不存在明显知识跳跃。
3. 每集围绕一个具体问题或认知收获，标题不再像章节目录。
4. 每集包含听众钩子、核心主题和二至四个递进核心要点。
5. 表达轻松但克制，具备故事性、反差感和清晰因果链，同时没有强行玩梗或模仿个人口头禅。
6. 每集使用的知识资产和原文索引完整、有效且可追溯。
7. 用户的集数、特殊要求以及项目级模型选择继续正确生效。
