# 分环节模型选择与专辑大纲选题增强设计

## 背景

现有专辑大纲能够覆盖拆书稿并保留知识资产和原文索引，但选题表达偏向知识点罗列，标题、核心主题和主要内容缺少问题意识、冲突感与连续收听动力。

本次同时增加项目级分环节模型选择。全局模型继续作为默认值，各内容项目可以按生产环节覆盖模型。

## 目标

1. 每个内容项目可以分别选择章节拆书、思维导图、专辑大纲、声音细纲、声音初稿和声音终稿使用的模型。
2. 专辑大纲默认使用模型预设 `kimi-k3`，其他环节默认跟随全局模型。
3. 专辑大纲以听众关心的问题为中心组织，而不是机械复述章节目录。
4. 标题灵活使用问题、冲突、悬念、反常识、因果追问等表达方式。
5. 每集包含明确的核心主题和递进的核心要点。
6. 全部内容继续来源于逐章结构化拆书稿，并保留知识资产 ID 与原文索引。
7. 用户输入的期望集数和专辑特殊要求继续拥有最高优先级。

## 非目标

- 不增加第二次“标题润色”模型调用。
- 不删除或替代现有全局模型选择。
- 不更改专辑大纲审核页的核心数据结构。
- 不允许为了吸引力引入拆书稿之外的事实、观点或案例。
- 不为 JSON 修复和长文本压缩增加独立的可见模型选择。

## 模型配置层级

模型配置分为两层：

1. 全局默认模型：保留现有全局模型切换。
2. 项目级环节覆盖：每个内容项目保存六个可空的模型选择。

项目级环节包括：

| 环节 | 覆盖的模型任务 | 默认值 |
| --- | --- | --- |
| 章节拆书 | 章节分析、人物关系提取 | 跟随全局 |
| 思维导图 | 全书思维导图 | 跟随全局 |
| 专辑大纲 | 专辑目录与选题设计 | `kimi-k3` |
| 声音细纲 | 叙事类或非叙事类声音细纲 | 跟随全局 |
| 声音初稿 | 声音初稿 | 跟随全局 |
| 声音终稿 | 口语化终稿 | 跟随全局 |

“跟随全局”在数据中保存为空值，不复制当时的全局模型 ID。因此用户以后切换全局模型时，所有未覆盖的项目环节会自动使用新的全局模型。

新建项目时，专辑大纲模型写入 `kimi-k3`，其余环节为空。已有项目迁移后使用相同规则：专辑大纲默认 `kimi-k3`，其他环节跟随全局；迁移不重新生成或改写任何已有内容。

项目表新增 `model_overrides_json`，使用以下稳定环节键：

```json
{
  "book_analysis": null,
  "mind_map": null,
  "album_outline": "kimi-k3",
  "episode_outline": null,
  "episode_draft": null,
  "episode_final": null
}
```

`null` 表示跟随全局。后端读取时补全缺失键，保证旧数据和后续新增环节能够兼容；写入时只接受模型目录中存在的模型 ID 或 `null`。

项目详情接口同时返回：

- `model_overrides`：项目保存的六项覆盖值；
- `effective_models`：结合当前全局模型解析后的六项实际模型 ID 和显示名称；
- `available_models`：继续复用全局设置接口的模型目录，不在项目记录中复制。

项目模型设置通过独立的项目级更新接口保存。请求包含单个环节键和模型 ID 或 `null`，避免编辑一个选择框时覆盖其他环节的并发修改。

## 模型路由

每个模型任务启动前，工作流根据项目 ID 和环节解析有效模型：

1. 环节有项目级模型 ID 时使用该模型；
2. 环节没有覆盖时获取当前全局模型快照；
3. 把解析后的实际模型 ID 写入任务或批次记录；
4. 任务启动后锁定该快照，运行中修改项目设置只影响下一次任务。

批量声音生产中，每条声音的三个步骤分别读取项目的声音细纲、声音初稿和声音终稿设置。单条重跑使用相同规则。

辅助模型调用不增加独立选项：

- JSON 修复继承发生错误的原任务模型；
- 人物关系提取继承章节拆书模型；
- 需要模型参与的长文本压缩继承对应的思维导图或专辑大纲模型；
- 如果思维导图与专辑大纲模型不同，超长输入分别生成并按任务与来源版本缓存；
- 确定性结构化压缩不调用模型。

如果项目选择的模型不存在、无法初始化或调用失败，对应环节明确失败并显示模型名称与错误，不静默回退。

## 项目模型配置界面

项目页增加可折叠的“模型配置”区域，包含六个下拉框。每个下拉框均提供：

- “跟随全局 · 当前模型名”；
- 模型目录中的全部可用模型。

专辑大纲选择框初始显示 Kimi K3。其他选择框初始显示当前全局模型。用户修改选择后自动保存到当前项目，无须点击额外保存按钮。

“生成思维导图与专辑大纲”区域同时显示两个环节实际将使用的模型，声音批量生产区域显示细纲、初稿和终稿模型，避免用户只能在配置区查看。

切换项目时重新读取该项目设置。保存失败时恢复界面中的旧值并显示错误，不能造成界面已切换但后端未保存的假象。

## 专辑组稿方法

提示词要求模型在输出前完成以下内部规划，但不输出分析过程：

1. 识别全书的核心问题、知识主线和读者最关心的现实问题。
2. 按内容关系组合拆书稿，而不是默认一章对应一集。
3. 为每集选择一个能够独立成立的核心问题。
4. 设计全专辑的收听顺序，使内容形成“发现现象—追问原因—解释机制—讨论影响或出路”的递进关系。
5. 再将每集绑定到实际使用的知识资产和原文索引。

内容足够且逻辑相关时，可以合并相邻章节或子主题；不得合并无关知识模块，也不得为了凑集数重复同一观点。

## 标题要求

标题优先使用以下方式，但不强制所有标题采用同一形式：

- 反常识或异常现象；
- 直接提出听众想知道的问题；
- 呈现两个力量之间的冲突；
- 揭示一个机制、误区或隐秘影响；
- 使用具体人物、现象、案例或概念作为入口。

标题需要准确反映拆书稿内容，避免：

- “第一章解读”“核心概念介绍”等目录式标题；
- “震惊”“颠覆认知”等空泛标题党；
- 把模型推断包装成原书结论；
- 多集使用高度重复的句式。

## 单集内容结构

保持现有 JSON 字段：

```json
{
  "title": "声音标题",
  "main_points": "核心主题：……\n核心要点：1. ……；2. ……；3. ……",
  "section_identifier": "章节与子主题说明，包含原文索引",
  "knowledge_item_ids": ["knowledge_xxx"],
  "content_type": "解读类"
}
```

字段要求：

- `title`：简洁、具体、有收听吸引力，并忠于拆书稿。
- `main_points`：
  - `核心主题`用一句话说明本集要解决的问题或揭示的机制；
  - `核心要点`通常为三个递进要点，可根据实际内容使用两至四个；
  - 要点优先覆盖“具体现象或故事—解释机制—现实影响或启示”，不机械套模板。
- `section_identifier`：保留人类可读的章节、子主题说明和精确 `content_index`。
- `knowledge_item_ids`：只列出本集实际采用的知识资产。
- `content_type`：保持现有解读类、过渡类约束；仅在确有必要时生成过渡类。

后端继续以知识资产来源表为准校正原文索引，避免模型返回的索引与资产实际来源不一致。

## 用户要求的优先级

提示词按以下优先级处理约束：

1. 事实必须来自拆书稿，引用必须可追溯；
2. 用户填写的专辑特殊要求；
3. 用户填写的期望集数；
4. 本设计中的选题与表达原则；
5. 模型根据内容密度自行判断的组稿策略。

如果用户未填写期望集数，模型根据知识模块数量与单集内容完整度决定，不设置固定下限。

## 错误处理

- 项目选择的模型不存在或无法初始化：对应任务失败，其他环节不受影响。
- 模型输出不是有效 JSON：沿用现有结构化输出错误处理。
- 输出缺少标题、核心主题、核心要点、知识资产或索引：校验失败并保留可重跑状态。
- 输出引用不存在的知识资产：校验失败。
- 模型索引与知识资产来源不一致：后端使用资产的权威来源索引进行校正，并返回校正提示。
- 项目模型设置保存失败：前端回滚选择并显示错误。
- 批量声音中的单条或单阶段失败：继续处理其他声音，保留实际模型 ID 和失败原因。

## 测试

### 提示词测试

- 包含问题导向、内容递进、标题多样性和禁止标题党的要求。
- 包含核心主题与核心要点的输出规范。
- 保留知识资产 ID、原文索引、集数和特殊要求约束。

### 模型路由测试

- 新项目的专辑大纲默认使用 `kimi-k3`，其他环节跟随全局。
- 已有项目迁移后获得相同默认规则，已有内容不变。
- 项目环节设置为空时使用当前全局模型。
- 项目环节设置了模型时使用覆盖模型。
- 同一次生成中的思维导图和专辑大纲可以使用不同模型。
- 章节分析与人物关系提取使用章节拆书模型。
- 批量生产的三个阶段分别使用各自模型。
- JSON 修复继承原任务模型。
- 运行中修改设置不改变已经启动的任务快照。
- 所选模型不可用时只将对应任务标记为失败。

### 工作流测试

- 有效结果可保存为声音列表。
- `main_points` 包含核心主题和核心要点。
- 来源资产和原文索引完整保留。
- 用户指定集数与特殊要求被传入提示词。

### API 与界面测试

- 项目详情返回六项模型设置和解析后的有效模型信息。
- 项目模型配置可单项更新并持久化。
- 非法模型 ID 被拒绝。
- 六个选择框正确显示“跟随全局”和项目覆盖状态。
- 自动保存失败时界面回滚。
- 生成区域正确显示本次将使用的模型。

## 验收标准

1. 新建或迁移后的项目中，专辑大纲默认显示 Kimi K3，其他环节显示跟随全局。
2. 六个环节均可独立选择模型并在重新打开项目后保留。
3. 未覆盖的环节会随全局模型切换，已覆盖的环节不受影响。
4. 任务记录能够显示实际使用的模型。
5. 新生成的每集都有具体、有吸引力且忠于原书的标题。
6. 每集主要内容明确区分核心主题与核心要点。
7. 相邻单集形成可理解的内容递进，而不是简单复制章节顺序。
8. 每集都保留有效的知识资产 ID 和原文索引。
9. 现有前后端测试通过，并新增项目模型配置、路由与提示词测试。
